### F2 执行时序、桥授权与恢复

- 19 个协作工具提供字段、必填项、枚举及说明，真实 MCP tools/list 和协议回归均覆盖；身份不进入模型参数。恢复 thread 显式携带 cwd、模型、角色、权限及桥配置。
- 派发按成员并行、同成员串行；唤醒信号合并且不丢失。停止取消 RPC 等待并遵守截止时间。启动响应只确认已接受事实，不覆盖审批/完成/未知状态；原生 turn/started 先绑定身份，重复的前驱完成通知不能结束后继。回调按发出事件的 runtime/epoch 处理，结束 turn 时使其未决定原生卡失效。
- 真实测试纠正了两项原假设：`auto` 并非协作工具免审批，CoBot 自有桥应使用 `approve`，命令/文件原生审批仍启用；已加载的 Codex thread 会保留 MCP 进程，resume 新环境变量不会替换它的旧令牌。第一版轮换令牌的实现因此在第二轮真实调用中失败，未被记为通过。
- 最终采用同一受管桥连接、按 Run 激活的执行授权和 Codex 原生 `_meta.x-codex-turn-metadata` 身份：桥只转发原生 thread/turn，服务端核对活动 Run/代际/会话，模型参数不能指定来源。Run 结束立即停用授权，闲置/过期请求被拒绝，只有宿主领取新 Run 才能重新激活；显式撤销不被下一轮静默恢复。核心重启重签发，凭据值仍只在内存/受管通道中。保留连接标识是适配引擎生命周期，不是让旧执行获得后继权限。
- 目录改绑与领取派发/启动 runtime 互斥，活动和 unknown Run 均拒绝改绑；旧 runtime 关闭后新启动使用新 cwd。恢复选项先查询精确旧 thread/turn 的终结事实；缺少身份或仍在执行时保留 unknown 和待决定卡，不消耗决定，不重跑。缺身份的卡提供禁用原因，前端展示在 F4 完成。

## F3b（2026-10-16）：审批反馈、候选绑定与原子重试

- 合并/增员决定、成员创建、结果消息、唯一投递及请求重放记录在同一事务提交；结果回到申请成员，沿用任务/来源运行/因果链。queued/sent/unknown/expired 表示投递事实，不把决定等同于已执行。
- 合并申请保存任务版本、候选/目标、团队目录、执行目录和具体证据快照。证据须属于任务且对应候选，并有测试/审查报告；这是 Agent 提交的证据，不冒充 CoBot 自己执行 Git/测试。决定时与派发时都复核；事实变化拒绝旧批准，仍可拒绝关闭过期申请。
- HTTP/MCP 状态写操作的幂等记录与业务变更同事务保存；同身份/动作/键的并发重试串行，参数或目标变化冲突，换应用实例仍可重放。原生审批重试不重复发送 RPC；完成或新审批先于回执时不会被改回运行中。
- 链路与恢复审批的决定和产品状态变更同事务；新链路卡片绑定 epoch，启动兼容修复不跨越新的待审批卡片。恢复仍先向 provider 核实准确 turn 的终态，网络检查不占 SQL 事务。
- 团队创建/重试/目录改绑先提交相同的预留实体，再准备文件；失败或准备中重启留下可重试 error。标记重建和中断先保存意图，重复请求返回已知结果，不盲目重发未知外部操作。一次性登录/授权秘密不进入重放记录。
- 可变实体更新/决定/转交接受要求正数 expectedRevision；DELETE 团队/成员用 Idempotency-Key + If-Match，拒绝头/正文版本冲突。记忆内容不可变，删除是幂等墓碑，只需要请求键。客户端新操作使用 UUID；兼容有界的不透明请求键。
- 新增迁移 00009：审批结果关联 delivery；已有决定/原生审批语义保留，沿用迁移前一致性备份。OpenAPI 与两端生成类型同步。
- 验证：`go test ./... -count=1 -timeout=90s`、`go vet ./...`、前端 typecheck、31 项单测通过。新增并发重复创建团队/任务/成员、重放记录失败整体回滚、跨 App 重放、缺版本/DELETE 头、合并批准/拒绝反馈、证据/版本/目录失配、成员与决定整体回滚、原生回执竞态与重复回复测试。真实模型闭环和前端新入口在 F4/F5 继续验收，不在这里宣称完成。
