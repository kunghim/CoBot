# 产品现状

适用：梳理需求、判断某个能力“现在有没有”、读懂业务代码里的概念。现状以代码为准，本文与代码不一致时以代码为准并修正本文。

## 定位

CoBot 提供聊天与团队两种入口：聊天是无项目的独立 Codex 会话，团队通过多个外部智能体协作。
CoBot 负责团队、角色、需求、卡片、消息、审批、用量和恢复；具体执行（模型、工具、shell、文件）交给外部智能体。
目前只接入 ChatGPT 桌面端内置的 Codex（`codex app-server`），不使用独立安装的 CLI；CoBot 保持独立的登录、配置与数据目录。macOS 和 Windows Store 包可自动发现，其他平台暂不自动发现。编程是当前场景，产品不限定只做编程。

## 术语

| 术语 | 含义 | 代码 |
| --- | --- | --- |
| 团队 | 一组成员共享一个工作目录；每个团队一个 app-server | `internal/domain/team.go` |
| 成员 | 团队里的一个角色实例，对应一个 Codex 线程 | `internal/domain/team.go` |
| 项目经理 | 团队的领队角色：起草需求、提出链路、验收汇报 | `internal/roles/defaults/leader.json` |
| 需求 | 项目经理写的需求文档 + 用户确认过的链路 | `internal/domain/requirement.go` |
| 链路 / 环节 | 需求的有序处理步骤，每一环是一张卡片或一次用户确认 | 同上 |
| 卡片 | 交给某个成员的一环工作；业务只靠卡片推进 | 同上 |
| 交接 | 成员完成、退回、上报或交回卡片（`handoff`） | `internal/app/relay.go` |
| 留言 | 成员之间发消息（`send_message`），不唤醒、不推进业务 | 同上 |
| 协作链预算 | 机器人互相唤醒消耗的次数上限，超限等用户确认 | `internal/app/chains.go` |
| 审批 | 原生工具审批、协作链超限确认、中断恢复三类 | `internal/domain/conversation.go` |
| 子智能体 | 成员在 Codex 里派生的子会话，归属该成员 | `internal/app/subagents.go` |
| 数据根 | 一个 profile 的全部本地数据；开发 `~/.cobot-dev`，正式 `~/.cobot` | `internal/platform` |

## 已实现

- 聊天 / 团队模式切换，分别保留聊天与成员选择；新用户默认聊天，已有团队用户保留团队入口。
  Logo 位于主导航的主页按钮上方，不显示 CoBot 字标；模式切换固定在二级菜单右上角，开关固定在会话区左上角，按实际显示的栏目对齐；收起菜单时隐藏模式；macOS 窗口态单独避让系统按钮，全屏取消预留，不横向挤动控件；侧栏新建位于列表标题上方，不另加大顶栏；聊天输入独立于团队输入，新聊天只显示一句本地时间问候，输入草稿期间不变。
- 会话搜索：标题栏搜索框按标题和消息内容查聊天与团队成员，结果分组限量、按最近活动排序，选中跳进对应会话；已归档与已删除的会话不参与匹配。搜索框跟随可见侧栏，窄窗口先收缩它；macOS 非全屏时位于系统按钮预留行之下，不与红绿灯重叠。
- 无项目聊天：文本多轮、模型选择、流式回复、停止、历史分页、重命名与删除；首次发送才保存聊天。
  模型在首次发送时确定，聊天不装配团队角色或协作桥，原生工具、审批与提问由 Codex 执行并在聊天内呈现。
  工作目录由应用单独管理，删除聊天保留生成文件；状态未知的执行不自动重放，核实原生轮次结束后才能继续。
- 聊天可置顶、归入单层分区，以最近活动或手动顺序排列；按分区和合并显示只改变侧栏视图，不改变目录或线程上下文。
  设置中的“已归档”统一管理聊天和团队，保留各自恢复与删除规则。聊天归档同步原生线程；未确认的归档操作保留待核实状态，期间不能发送、删除或反向操作。

- 团队选择一个成员共享的工作目录；每团队一个 app-server，每成员一个 Codex 会话。
- 软件场景角色：项目经理、产品经理、全栈工程师、测试工程师、评审员（`internal/roles/defaults/`）。
- 需求接力：需求文档 + 用户确认的链路，卡片串行流转，详见 [接力规则](relay.md)。
- 用户可以直接找任一成员，也通过确认、验收、提问和原生审批作决定。
- 模型属于成员：每个已配置的供应商同时可选，各有开关（默认开；关掉后其模型不出现在选择器里，配置保留）；
  ChatGPT 账号也是一个供应商，总在列表里，可关不可删。没选模型的成员跟随设置里的默认模型。
- 成员换到另一个供应商，或网关里换到另一家的模型时，开一条新线程：旧线程原样保留，新线程第一轮会被告知旧会话记录在哪。
- 团队级设置：思考强度、权限模式。
- 一轮结束时卡片还没交接，成员会被提醒：每张卡片最多两次，第二次在换新线程之后；之后卡片保持原样留给用户处理。
- 已存记忆可查看、删除，并随线程指令带给成员；模型没有写入记忆的工具。
- 子智能体的步骤、审批和用量归到成员，但不能代成员交接、提交需求或向用户提问。
- 团队浏览器工具与实时面板；工作区（标签区）第一阶段。
- 服务只监听回环地址；打开页面即获得会话，一次性链接只作备用。
- 头像：公开系列、本地缓存、本机上传。
