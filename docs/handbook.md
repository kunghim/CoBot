# 共建者手册

适用：第一次参与 CoBot 开发，或想了解这套 AI coding 规范怎么运转。`docs/` 下的其他文档主要写给编码智能体看；
这一篇写给人，讲清楚整体怎么配合，细节都链接到对应文档。

## 一、文档是怎么组织的

智能体每次会话都会先读仓库根目录的 [AGENTS.md](../AGENTS.md)。它很短，只有几条始终适用的规则和两张路由表：

- **改到哪里，读哪份规则**（`docs/rules/`）：改接口读接口规则，改迁移读迁移规则……没动到的目录，对应规则就不读。
- **做到哪一步，读哪份流程**（`docs/workflows/`）：开始实现、验证、交付、写文档各有一份。

另外几类：

| 目录 | 内容 | 什么时候看 |
| --- | --- | --- |
| `docs/product/` | 产品现状、接力规则、决定索引 | 梳理需求、判断某能力有没有 |
| `docs/pitfalls.md` | 每次都会碰到的坑（数据根、登录、端口、新 worktree） | 跑测试、起服务前 |
| `docs/reference/` | 依赖、升级回滚、发布、Issue 分诊、hook 排障 | 很少需要 |

文档只写读代码得不到、或者容易做错的东西。模块列表、版本号这类能从代码查到的不写，免得过期。
完整索引见 [docs/README.md](README.md)；`node scripts/check-docs.mjs` 会检查文件名、索引和链接。

## 二、你的私人空间：主目录的 `.local/`

方案、讨论、验收记录、个人笔记这些不该进项目的东西，放在**主检出目录**（第一次 clone 出来的目录）的 `.local/`。

- 它被 CoBot 仓库忽略，内容永远不会进入代码提交或 PR。
- 它自己是一个独立的 Git 仓库，推到**你自己的**私有仓库或 fork 上，有版本记录，换电脑能取回。
- 所有 worktree 都读写主目录这一份，不在 worktree 里另建。

第一次建立：

```sh
git init .local
git -C .local remote add origin <你的私有仓库或 fork 地址>
```

换电脑：`git clone <同一地址> .local`。远端不能是上游 `kunghim/CoBot`。

如果你在 worktree 里用 Claude Code 或 Codex，需要在它们的本机配置里把 `<主目录>/.local` 加为可写目录，否则会被拦。
目录结构、命名和归档方式见 [文档流程](workflows/docs.md)。

## 三、智能体在 Git 上会怎么做

这些规则写在 [交付与同步流程](workflows/deliver.md)，所有智能体都遵守：

- **不会主动问你要不要 commit、push、开 PR。** 做完只汇报结果，需要时你直接说。
- **你说“提交”“拉取”“推送”时，代码和 `.local/` 笔记一起处理**：提交本任务写过的笔记、`pull --ff-only` 笔记、推送笔记。
  笔记两边都改过无法快进时，它会停下来告诉你。
- **一次授权只管当时那批改动。** 你让它推送或开 PR 之后，它开始做下一个需求时不会沿用这次授权；
  新需求没经过你明确验收，不会推送、不会开 PR。它自己跑通测试不算验收。
- 只 `git add` 具体文件，不 reset、stash、rebase 或强推。

## 四、分支与 PR

- 从上游 `dev` 拉短期主题分支，PR 以 `dev` 为目标；只有本仓库的 `dev` 能晋级到 `main`，CI 会拒绝其他路线。
- PR 按模板写四部分：问题与关联、改动后的行为、实际验证、兼容性与数据影响。
- 详细要求见 [CONTRIBUTING.md](../CONTRIBUTING.md)；维护者的合并、晋级与发布见 `docs/reference/`。

## 五、验证要说实话

- 测试只用 `.tmp/test-runs/<名称>/` 这类临时数据根，不碰 `~/.cobot`（正式数据）和 `~/.cobot-dev`。
- 需要真实 Codex 时，复制一份已登录的测试数据根再用，不用你日常的 Codex 登录；会消耗账号额度。
- 汇报时分开写三类：自动化测试、真实 Codex 验证、原生平台验证。编译通过不等于安装通过，假引擎通过不等于真实 Codex 通过。

细节见 [验证流程](workflows/verify.md) 和 [踩坑记录](pitfalls.md)。

## 六、规则要改怎么办

规则写在 `docs/` 里，和代码一样通过 PR 修改。同一条规则只写在一处，其他地方链接过去。
发现智能体反复犯同一个错，优先考虑能不能加一个检查脚本；查不了的，才写进对应的规则或踩坑记录。
