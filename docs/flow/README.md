# CoBot 接力链路 · 交互式演示

一张卡片如何被交接、被打回、重跑，最后落到你的验收卡。

单文件、零依赖，直接用浏览器打开 `index.html` 即可。

```
open docs/flow/index.html
```

## 画的是什么

CoBot 的协作模型，不是「谁和谁说话」的聊天图：

- **节点是链路环节，不是角色。** 一条由用户确认过的链路依次走过
  需求评审 → 产品设计 → 测试用例 → 实现 → 测试 → 代码评审 → 验收汇报。
  同一角色可以在链路里出现两次 —— 产品经理负责需求评审与产品设计，
  测试工程师负责测试用例与测试执行。
- **卡片只往前���，一环一个负责人。** 中间环节不经人转手：上一环交出，
  下一环直接接手。
- **退回只回到产出它的那一环。** 测试环节发现 bug，退回实现环节重跑；
  评审环节打回，同样退回产出它的那一环。重跑之后，链路继续往下走。
- **留言和卡片是两种东西。** 留言（`send_message`）只留字，不唤醒对方；
  唤醒与确认走卡片。线型上分开：实线是卡片交接，点线是留言，上拱虚线是退回重跑。
- **起点和收尾都是你。** 项目经理写下需求文档、挑出链路，提交给你确认；
  链路的最后一环是项目经理的验收汇报，它变成你的验收卡。

## 剧本

一份需求走完整条链路，内嵌三次失败回合：

| 幕 | 环节 | 发生了什么 |
| --- | --- | --- |
| 1 | 需求与链路 | 你提出需求，项目经理写需求文档、选定链路，等你确认 |
| 2 | 需求评审 | 「全文搜索」没定义范围 → 退回 → 重跑 → 通过 |
| 3 | 产品设计 | 写产品文档与原型；编辑器形态由你拍板 |
| 4 | 测试用例 | 38 条用例；插播一条你的留言 |
| 5 | 实现 | 读需求+设计+用例改代码，先自测一轮 |
| 6 | 测试 | bug#7 漏召回 → 退回实现环节 → 修复 → 回归通过 |
| 7 | 评审与验收 | 评审打回（重试预算没测试覆盖）→ 重跑 → 验收汇报 → 你的验收卡 |

示例项目是 NoteMark —— 一个本地 Markdown 笔记应用，要标签和全文搜索。
换成别的项目，改 `MAIN` / `ROLE_SCRIPTS` 里的文案即可。

## 交互

- 点任意环节卡 → 其余压暗，只亮它这一环，循环播放该环节的小剧本；再点一次回到全景。
- 幕进度条显示当前走到第几幕。
- 计数器：当前阶段 / 次交接 / 次退回 / 次用户决策，每轮从零开始。
- 速度滑块 0.25×–2× 连续可调，数值记在 `localStorage`。
- 复选框可关掉「插播留言片段」。

## 实现

零依赖：inline CSS + SVG 覆盖层连线（`getBoundingClientRect` 量取、ResizeObserver 重算）、
沿路径发包（`getPointAtLength`）、async/await 剧本编排、`gen` 代数失效（上一轮的定时器自动作废）、
CSS keyframes 微动效。

**时钟用 `setInterval` 而不是 `rAF`。** rAF 在后台标签页和部分 WebView 宿主里会完全停摆，
那样演示会永远停在第一幕；`setInterval` 最多被浏览器节流，不会停。也不做可见性门控 ——
`IntersectionObserver` 在部分宿主里会把「在视口内」判成 false，`document.hidden` 又和真实
可见性对不上，任何一个用错都会让演示卡住。

调试钩子：宿主若仍然节流，控制台可用 `__demo.step(ms)` 手动泵时钟，`__demo.stats()` 读计数器。
