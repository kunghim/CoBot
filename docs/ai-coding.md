# AI coding 规范

本文说明编码智能体如何参与 CoBot 开发，从 [AGENTS.md](../AGENTS.md) 进入，
与[开发指南](development.md)和[贡献指南](../CONTRIBUTING.md)配合使用。
本文约束修改本仓库的编码智能体；产品内置角色指令和协作工具属于另一类业务资源。

## 从任务与工作区开始

修改前检查 `git status --short` 和当前分支，了解已有改动，保留不属于本任务的工作。
在指定工作目录中开发，不另建嵌套仓库，不切换到历史实验项目。

先明确预期结果与验收条件，区分明确要求、实现选择和未决产品问题。
常规、可逆的实现细节自行判断；缺失信息会实质影响范围或正确性时再询问，同时继续不依赖答案的工作。
不重复询问已经决定的事项。

遵循用户当前明确的任务决定。若决定改变了公共项目要求，同步更新对应的公共文档。
共建者的私人笔记只提供本机上下文，不自动成为所有人的共同要求。

## 按需获取上下文

修改行为前阅读相关源码、调用方和测试。可用时优先用 `rg` 或 `rg --files` 搜索。
按任务补读模块资料，不要求每次通读全部历史文档。

若 `.local/README.md` 存在且非空，先阅读，再按需读取相关引用；缺失或为空时直接继续，无需索取。
不编造缺失的私有文档，不按文件名推断需求，也不因私有资料缺失阻塞开发。

将文档与当前代码核对，分清已确认需求、当前实现、候选方案和历史测试结果。
发现实质差异时说明，不把旧方案静默当作当前实现。
历史聊天和摘要可作为线索，不能是公共项目知识的唯一依据。

## 聚焦实现

较大任务在修改前简要说明改法和验证方式。
实现遵循任务范围和开发指南中的架构约束，避免无关清理、推测性抽象、额外依赖和未实现的界面入口。

在证据支持的范围内解决根因，沿用已有约定，检查受影响的调用方，
按需同步契约、迁移、翻译和文档。不能用模拟成功替代真实消息、任务交付、审批或恢复。

项目依赖按锁文件获取。判断工具缺失前，检查可用工具链和本机环境说明。
必需资源不可用时说明具体限制，不猜安装路径、不静默安装系统工具或修改全局设置。

## 协作并保留已有工作

多个会话修改相同文件前先协调责任范围，尊重现有 worktree 和其他会话的改动。
用户要求或确有隔离需要时使用独立 worktree，分支遵循贡献指南；核对起始 ref，并在返回的路径中工作。

不同工作目录不隔离运行中的服务、账号或数据根，并行开发与测试应使用不同的临时数据根。
私有 `.local/` 文件也不会随分支自动切换或出现在新 worktree 中，不默认复制其他共建者的私人资料。

拆分工作时说明各部分的范围和预期结果，检查产出后再整合。
协作者声明完成不等于已经验证。

## 验证结果

按受影响行为选择检查。重要正确性变化应增加或更新有针对性的行为回归，避免只复述实现的测试。
先做相关检查，提交前再执行开发指南要求的检查。
检查通过后，没有新原因就不反复运行无关检查。

检查最终差异中的意外改动、生成文件漂移和私人内容。
不能为通过检查而放宽沙箱、审批、认证或 hook 信任。
区分自动化、真实引擎与原生平台验证，明确失败、跳过的检查和未测范围；
不能凭 mock 或模型未经核实的报告宣称成功。

## 更新知识与交付

共享行为、命令或需求变化时，更新对应的权威公共文档，其他位置引用，避免重复维护。
不把工程默认值倒写成用户曾经确认的决定。

私人讨论、个人笔记和临时分析写入 `.local/`，必要时维护其可选索引。
具体分类和文档状态遵循开发指南；形成决定后更新知识入口，被替代资料转入归档。
历史验收保留当时版本与范围，未决问题先核对现行代码，再决定是否继续列为待办。
不将私人提示词、路径、录制或个人偏好复制到公共文档。
共同项目要求应在没有这些私人记录时仍可理解。

分支与 PR 遵循贡献指南。暂存前检查差异和工作区，只使用 `git add <specific paths>`，
不用 `git add .`、`git add -A` 或 `git commit -a`。
没有明确授权，不执行 reset、stash、rebase、丢弃他人改动或强推。
用户要求或授权后才提交，提交信息用清晰的英文；推送或发布需要明确授权。
同一动作已经获得授权时，无需再次询问。

交付时说明改动后的行为、相关文件、实际验证和剩余限制，必要时说明保留的无关改动。
对话使用用户偏好的语言，代码标识符和提交信息使用英文；公共文档语言遵循开发指南的约定。
