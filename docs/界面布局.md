- 性质：需求与交互草案；具体标签和文案尚未全部定稿；产品规则见[需求文档](需求文档.md)，实现建议见[首版开发方案](首版开发方案.md)。
- 原型保留名称、目录及成员字段，具体目录文案以后按 R01 核对；本轮不修改原型。
- 本机可选预览（docs/prototypes，Git不包含）：首页交互草案（仅本机归档，非必读），离线打开即可。翻页与审批只修改本页示例数据，刷新恢复，不调用模型、不写入真实目录。

一级导航常驻，团队列表与右侧工作面板独立收起。中间始终是用户与当前 bot 的会话。两侧用图标开关，有悬停说明、可访问名称和展开状态；收起后恢复入口留在会话头部。首页按钮负责导航，不兼做列表开关。窄屏以覆盖式列表或工作面板呈现，仍可打开和关闭。

## 一级导航与团队列表

- 一级只用图标：顶部 logo、首页入口，底部设置。搜索、定时任务、工作面板等是未来扩展的理由，本轮不实现、不提前放按钮。
- 二级团队列表展开后，顶部保留 cobot 徽章；「新建团队」「待你处理」与团队 / 成员结构不变。设置入口移到一级底部。
- 「待你处理」汇总跨团队请求；点击后进入有请求的队长会话并定位待审批卡，不跳到只展示历史的审批页。
- 团队内为队长与所属成员的两级树，成员下不挂沟通记录。
- 状态通过列表徽标体现：正在工作、正在写回复、等你审批、需要输入、中断、空闲、失联待核对。
- 队长行保留团队名与队长身份；工作目录在队长会话头部集中显示；目录信息同时提供给全体成员的 Agent 上下文。两侧收起时头部仍明确显示当前 bot 与团队。

## 会话区

- 队长头部显示团队名与所选工作目录；成员头部显示名字、所属团队和当前任务，不重复显示目录。
- 删除成员页面原来的「对话 / 私聊记录 / 记忆」标签，协作记录与记忆统一移到右侧。
- 消息流只放用户与当前 bot 的消息，以及派发、交接、正在沟通等简短提示。点击沟通提示打开相关成员的右侧协作记录。
- 不显示协作链计数、轮数上限、风险区、`.cobot` 状态或 token 统计。
- 输入框上方显示当前待审批卡与必要的工作状态，不显示「等你审批」；成员会话只提示当前成员正在进行的工作，等待状态留在列表。

## 审批卡与恢复卡

- 卡片放在输入框上方，一次一张；右上角显示当前位置 / 尚待处理总数（如 `‹ 1 / 2 ›`），支持上一张、下一张。翻页只查看，处理后移除当前卡，更新总数并展示相邻未处理卡，不自动轮播。队长会话显示全团队待处理卡；成员会话只显示该成员发起的卡。中断恢复卡在队长会话显示。
- 处理后卡片立即消失，不在消息流留下记录；所有入口同步生效。右侧审批页保留历史。
- 安全审批显示发起者、命令或动作、真实理由；选项为「允许一次」「总是允许（这个 bot）」「拒绝」。
- 协作确认描述具体下一步与需要决定的事项，不显示轮数与风险区。草案选项为「继续」「附一句指示再继续」「停止当前协作」。
- 恢复卡显示中断任务、已知成果/工作位置和变更；编程可附任务分支，选项为「继续」「重跑当前工作」「放弃」。
- 移除「待你处理 N」标题、卡片上的审批记录按钮和剩余张数说明。右侧仍叫「审批」，只展示已处理记录，保留全部选项与所选项、发起者、动作、理由、申请和处理时间、处理入口；未处理的请求不进历史，也不在右侧重复提供操作。
- 内部轮次控制不删掉；仅因轮次触发时，卡片可写「下一步将继续推进当前任务，请确认是否按当前方向继续」，不虚构安全风险。具体措辞仍待确认，真实触发原因保留在后台。

## 右侧工作面板

面板头部始终标明当前 bot 与范围。五个入口为「任务、审批、动态、协作、记忆」；「协作」页的完整名称是「协作记录」。去掉原「团队」页。

| 入口 | 队长视图 | 成员视图 |
| --- | --- | --- |
| 任务 | 全团队任务与负责人，可展开看板 | 只显示自己负责的任务，展开后仍保持该范围 |
| 审批 | 全团队已处理历史 | 自己发起的已处理历史；由队长处理的也能看到 |
| 动态 | 全团队派发、交接、审批、恢复事件 | 与自己有关的事件 |
| 协作记录 | 队长与成员的沟通 | 当前成员与队长或其他成员的沟通 |
| 记忆 | 队长自己的工作方法和偏好 | 当前成员自己的工作方法和偏好 |

- 同一段双向沟通在双方的协作页可查看，点开后仍在右侧，标明参与者和「只读」；返回列表不会替换中间会话。想插话就给相关 bot 发消息。
- 切换成员时清掉上一人的协作详情，保留当前入口并按新成员刷新；无记录时明确显示空状态。
- 动态是事件记录，不是群聊。协作结论仍需写回任务，记忆仍只存工作方法和偏好。
- 用量未来单独做页面；名单和状态由侧边栏表达，目录由队长会话头部表达，不重复造信息页。

## 新建团队

- 名称、必选工作目录、可选初始成员；队长自动产生。不要求轮数、风险区和 token 预算。
- CoBot 默认工作区是 `~/.cobot`，用户仍需要选择团队工作目录；不要求目录是 Git 仓库。
- 拒绝重复及嵌套绑定；目录丢失、未知来源的识别信息等异常按 R01 给出可操作说明。
- 所选目录内 `.cobot` 交互资源及本地排除属于内部处理，不在日常界面堆叠配置说明。
- 所选目录信息提供给所有成员；界面保持队长头部集中展示，成员头部保留团队与当前任务。
- 指定资源不可用或权限不足时报告，选中路径不自动授权跨目录输出和删除。
