## 实现范围

- 协作链（G01/G02）：迁移 00004；用户消息开新链、Bot 间消息与转交归因发起者所在链；计轮与派发资格同事务；(chain, dispatchKey) 唯一防重投双计；限值建链时快照；风险区与超限唤醒不启动，链状态机 active/evaluating/awaiting_approval/stopped。
- 风险评估（G03）：风险区内由模型在独立 read-only 会话判断（无协作工具、不入 provider_sessions、不是成员、不计业务唤醒）；只认结构化 continue/ask，失败/超时/不可解析一律回落用户卡；硬上限永不给模型看；评估用量 purpose=risk_eval 记团队账。
- 用量账本与预算（G06/G07/G08）：迁移 00005；(epoch, thread, turn) 唯一、快照原地更新不累加、cached 不重复计费；未报用量记 unknown；预算超限或 unknown 只拦新轮（队列保留、成员显示需要输入），提高/取消预算或补录用量即恢复。
- 记忆（G04/G05）：迁移 00006；按 (团队, 成员, 来源, 归一化正文) 唯一，删除写 tombstone 使同源同正文永不自动重建；检索归属过滤在存储层、10 条/6000 字符上限、溢出上报；秘密形状与超长写入拒绝；MCP remember/search_memory（19 工具）；BuildContext 附带成员自己的近期记忆。
- 团队/成员生命周期（B04/B08/B09）：PATCH/DELETE /teams/{id}、archive/restore、DELETE /bots/{id} 与 openapi 再生成；归档前普查（执行/审批/在途转交）；删除两步制且零未完成工作，软删除+解绑+撤销桥凭据，用户文件与标记不删；队长不可删、有工作者点名拒绝；目录已有标记必须显式 adoptMarker。
- 退出与启动对账（H01/H03/H04/H05/H09）：Scheduler.Stop 先对全部在途 Run 请求中断再关停自有引擎（serve 入口 10 秒上限既有）；启动对账：非终态 Run 一律按未知落库并保留原 turn/epoch/投递事实、认领中投递翻 unknown、死连接原生审批失效记 expired、每未知 Run 恰好一张恢复卡（继续=保留未知事实/重跑=仅 unknown 投递重入队/放弃=取消），锁定成员禁止新派发、无关成员不受影响；二次恢复处理拒绝。
- 租约/hook/事件（H06/H07/H08）：每 2 秒刷新成员租约（10 秒有效、原子写、派发时即写）；MCP 桥转发副作用工具前本地校验租约（缺失/损坏/过期点名拒绝，读取放行），不依赖 HTTP；`cobot hook` 只执行团队 hooks.json 显式配置的 argv（未配置名如实报未覆盖、副作用 hook 先过租约、超时诚实上报不宣称可撤销）；事件逐条镜像 JSONL，启动按 id 幂等导入、损坏文件隔离为证据、导入后保留 7 天、20MB 容量只剪已导入、超限记一次 log.gap。

## 本阶段修复/澄清的真实问题

1. **风险区计次错位**：旧链测试假设风险区唤醒“不启动任何会话”，评估接入后唤醒 3 会先起评估会话；测试与产品语义同步为“评估会话不是业务唤醒”。
2. **评估看门狗随派发 ctx 早夭**：评估超时最初绑定派发的 30 秒 ctx，链会被永久卡在 evaluating；改为独立计时并在启动对账复位被打断的评估链。
3. **评估线程用量误记成员**：tokenUsage 事件经成员解析失败后曾按 run 记账；现按评估线程注册表改记 purpose=risk_eval。
4. **测试自身的派发竞态**：一棒的 turn 未结束时下一棒的唤醒会被“单活动 Run”规则正确拦下（产品行为），测试编排改为先结束上一棒。

## 已知问题与偏离

- 计轮/风险/预算的用户面目前经由既有审批卡与设置页表达；任务/协作/记忆面板的完整 Web 展示沿 M5 的五页要求收口（记忆检索的 MCP 与上下文注入已在 M4 落地）。
- M4 未新增 HTTP 接口，openapi 仅在 B04/B08/B09 模块扩展（PATCH/DELETE 团队、归档/恢复、删除成员、adoptMarker）并再生成，契约无漂移。
- `internal/contract` 生成类型与 HTTP DTO 的统一映射（M2 遗留）仍随 M4+ 接口扩展推进。
- 租约刷新与评估会话目前只覆盖活跃团队成员；归档团队成员不写租约（其派发本就被归档拦截）。
- 未偏离用户已确认决定；阶段顺序按开发方案 M4 五步执行完毕。
