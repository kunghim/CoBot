# 升级与回滚

- 核对日期：2026-10-20；代码基线：`6b7530c`。
- 适用范围：Windows MSI/ZIP、macOS 应用包和独立 server。
- 下载与平台验证范围以 [README](../../README.md) 及对应版本的发布说明为准。

## 升级前

正常停止 CoBot，等待当前实例退出，再备份整个数据根并记录旧版本和对应程序。
生产默认是 `~/.cobot`，开发默认是 `~/.cobot-dev`；指定了 `--data-root` 时以实际路径为准。
Windows 默认生产位置可写为 `%USERPROFILE%\.cobot`。应用程序目录与数据根是两处位置。

备份应保留数据库、配置、私有引擎环境及本地资源。只在服务停止后复制，不在 WAL 写入期间只复制 SQLite 主文件。
备份中可能包含账号与私人数据，不能提交 Git 或附到公开问题中。
启动迁移生成的数据库快照不能替代完整数据根备份。

## 按发行形态替换程序

| 形态 | 操作 |
| --- | --- |
| Windows MSI | 关闭 CoBot 后安装更高 MSI 数字版本的包；产品显示版本与 MSI 数字版本是不同字段 |
| Windows ZIP | 完整解压新版到新目录，启动其中的 `cobot-desktop.exe`，保留配套助手与声明文件 |
| macOS 应用包 | 退出应用，整体替换 `CoBot.app`；从 DMG 复制到应用程序目录，不只替换包内主程序 |
| 独立 server | 停止旧进程后替换可执行文件，再用原 profile/数据根启动 |

Windows MSI 与 ZIP 使用相同的五个发行文件：桌面入口、后台助手、控制台程序、项目许可证和第三方声明。
不要混用不同版本的 `cobot-desktop.exe`、`cobot-helper.exe`、`cobot.exe`。
macOS 的同版本助手位于应用包内，也应整体替换。

MSI 卸载或删除 ZIP 目录不会自动删除用户数据。更换安装形态也不能被当作清空数据库的操作。
当前不提供应用自动更新；头像库的“检查更新”只同步公开头像资源。

## 数据库迁移及兼容性

迁移在启动时自动向前执行。已有业务库在迁移前由 SQLite `VACUUM INTO` 生成一致快照；
迁移失败时不继续提供业务，也不自动降级。程序会拒绝打开高于其 `MaxSupportedVersion` 的数据库。

**从旧任务模型跨入接力模型时存在数据清理，不能视为保留全部旧任务的无损升级。**
[迁移 00023](../../internal/store/sqlite/migrations/00023_relay_requirements.sql) 会：

- 删除旧任务依赖表和转交表。
- 清空旧任务及交付证据。
- 删除关联旧任务或旧协作通知种类的投递，以及关联旧任务/旧类别的问题记录。
- 建立需求与链路结构，将任务表用于接力卡片。

这是迁移的实际 SQL 行为，不只针对某台机器的测试数据。若需要保留旧任务历史，升级前保存完整备份；
当前没有将旧任务自动转成新需求链路的转换程序。此影响应在跨越该迁移的版本发布说明中明确列出。

[迁移 00022](../../internal/store/sqlite/migrations/00022_fullstack_and_project_manager.sql)
调整内置成员角色，[迁移 00024](../../internal/store/sqlite/migrations/00024_avatars.sql)
增加头像字段与角色头像设置。[迁移 00029](../../internal/store/sqlite/migrations/00029_budget_overrides.sql)
[迁移 00030](../../internal/store/sqlite/migrations/00030_budget_resets.sql)
新增手动重置时间表。两者都只新增表，不改已有数据；但设置里已有的预算从此按天统计、隔天重置，
此前它是累计到底的。此影响应在跨越该迁移的版本发布说明中列出。后续升级继续逐项核对新增迁移，不能用本文替代具体版本的变更说明。

## 首次启动后检查

使用原来的 profile 与数据根启动，核对程序版本、团队、成员和引擎状态。
浏览器会话在有效期内可跨服务重启保留；失效时使用本次启动输出的一次性授权链接。
核对与本次升级相关的业务路径；不要把能打开界面当成全部验收通过。

原生 hook 的路径可能随程序版本变化。CoBot 会按[原生 hook 手动审查](hook-review.md)中的所有权与内容匹配规则处理授权，
授权失败时检查设置状态，必要时手动审查；不能通过关闭守卫或绕过信任让升级检查通过。

`runtime/instance.lock.guard` 由操作系统锁定，正常退出后空文件可能仍在。
不要通过删除它解除运行实例的锁，不在同一数据根并行运行新旧程序。

## 回滚

1. 停止新版，另行保存升级后需要留存的数据；回滚备份不能保留这段时间的新增业务。
2. 使用升级前完整备份恢复到独立、停止状态的数据根，配合旧程序及匹配的 profile 启动。
3. 核对恢复结果后再决定是否替换实际运行目录，避免盲目覆盖唯一一份数据。

不要让旧程序直接打开已迁移的新库，不手工运行 goose down 企图恢复已删除的旧任务。
迁移脚本中的 Down 定义不能重建已经丢失的业务记录。

## 签名、校验和与验收范围

项目采用 Apache-2.0，第三方来源见[依赖说明](dependencies.md)。
当前 Windows 包未签名；macOS 包使用本机临时签名，没有 Developer ID 签名或公证。
SHA-256 用于核对文件完整性，不能称为代码签名。

仓库已有 Windows 安装生命周期和 macOS ARM64 原生冒烟记录，但它们只对应各自记录的版本、环境和范围。
Windows 沙盒曾使用临时安全策略与 Runtime 注册修正，不能据此声明默认安全环境全部通过。
本轮文档整理未重新执行安装或真实 Codex 验收；新发布仍需核对同一批候选产物。
