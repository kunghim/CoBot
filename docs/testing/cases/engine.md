# Codex 引擎与版本兼容

引擎只从 `PATH` 找。实现里没有最低版本门禁（旧版 Codex 因带不动控制进程在握手时失败，报「引擎控制进程不可用」）。
最低支持版本不单列用例（原 E1）：它由门禁 A4 和 [接力](relay.md)、[模型](models.md)的真实用例覆盖。

| ID | 层 | 步骤 | 期望 |
| --- | --- | --- | --- |
| E2 | 回归 | 本机 Codex 桌面版自带的引擎在 `%LOCALAPPDATA%\OpenAI\Codex\bin\<哈希>\codex.exe`（可能有多个目录，取 `--version` 较新的）。在 `$R/real` 的**另一份副本**里，用设置接口的 `enginePath` 指向它。只读使用，不复制、不安装、不改 PATH | 握手通过；`cobot trace protocol` 对比基线，差异逐项说明；真实跑通一个三环小需求 |
| E3 | 回归 | 最新正式版 Codex | 需要下载，先问用户。不做就在结论里写明实际验证过的版本 |
| EN-1 | 回归 | 设置页「Codex 引擎」分区 | 显示版本、可执行文件路径、协议 app-server/stdio、安全钩子「已授权」；`GET /api/v1/engine` 与页面一致 |
| EN-2 | 回归 | 选一个需要大于引擎默认 272000 窗口的模型并发一轮；再在设置里看正在运行的引擎 | 引擎用生成的模型目录启动，该模型真的得到那么大的窗口；用旧目录运行的引擎被列出，空闲时可以重启；生成的目录没通过引擎自检时不会被使用；上下文压缩在会话里显示为一个步骤 |
