# 模型与供应商

官方账号在 `$R/real`；网关在 `$R/gw`（密钥用 DPAPI 绑定当前 Windows 用户，同一用户下复制目录就能用）。
需要官方账号和网关同时可用时，在 `$R/real` 里按 D2-1 的方式添加网关，key 请用户填。
模型属于成员，供应商各有开关，规则见 [产品现状](../../product/overview.md)。

| ID | 层 | 步骤 | 期望 |
| --- | --- | --- | --- |
| D2-1 | 回归 | 编辑一个已配的网关：key 框留空，重新拉取模型、搜索、勾选、探测、保存。另外用假 key 添加一个预设 | 留空时沿用原 key，能拉到模型；列表在弹窗内滚动、按名称排序。假 key 显示「密钥无效」；全部不通时阻止保存，但提供「仍然保存」 |
| D2-2 | 回归 | 停用一个供应商，再启用 | 停用后它的模型从所有选择器里消失，配置保留；启用后恢复 |
| D2-3 | 回归 | 给一个成员换模型；再改回「默认」 | 只影响这个成员；改回默认后跟随设置里的默认模型，下一轮生效（用协议记录核对） |
| D2-4 | 回归 | 跨厂商换模型：一个成员做到一半，官方 → 网关模型 → 官方，每次只发「继续」 | 每次换都开新线程，旧线程保留；新线程第一轮说清停在哪并接着做，不问用户；换回官方后不再出现「请求被拒绝」 |
| D2-5 | 回归 | 混合团队跑完一条链路：项目经理用官方账号，工程师和测试工程师各用一个网关模型 | 网关模型能正确调用 CoBot 工具（交接、查看卡片、团队浏览器），不出现 `unsupported call`、不把工具调用写成文字 |
| D2-6 | 回归 | 错误展示：错 key、网关不提供的模型、余额或额度不足（能遇到哪个测哪个） | 会话里显示可理解的原因和下一步，不显示原始 JSON 或 `data:{...}` |
| D2-7 | 回归 | 设置里改默认模型 | 没选模型的成员下一轮用新默认；轮次不卡、不排队 |
| D2-9 | 回归 | **模型目录**：在供应商的模型上展开「高级设置」；点「更新模型目录」 | 目录认识的内容（上下文长度、最大输出、输入类型、能力、思考开关和档位）只读，数字上限可改小；目录里的思考档位来自目录不能改；100 万以上上下文显示「1M」；更新目录能下载最新并显示整理时间。模型值必须用目录合法值（shape/eyes/color），编造值会被渲染回退 |
