# 数据存储与升级

升级用的数据根 `$R/upgrade` 来自**上一个已发布版本**生成的真实数据（例如 `~/.cobot` 的只读副本），schema 版本低于候选版本。
候选版本的最高 schema 是 `internal/store/sqlite/migrate.go` 的 `MaxSupportedVersion`。

| ID | 层 | 步骤 | 期望 |
| --- | --- | --- | --- |
| B1 | 回归 | 用候选版本启动 `$R/upgrade` | 自动迁移到最新 schema；`backups/` 里有迁移前的备份；启动日志没有错误 |
| B2 | 回归 | 在界面里核对老数据 | 团队、成员、消息历史、记忆、外观（主题、深浅色）、语言都在；有旧任务的团队，项目经理会话里有一条删除说明，写明删了几个、几个没完成、备份在哪；设置页供应商列表里有 OpenAI 官方账号，已启用 |
| B3 | 回归 | 内置角色 | 没改过的内置角色升级到新版；用户改过的保留原内容 |
| B4 | 回归 | 停止核心，用上一个版本的程序打开 `$R/upgrade` | 明确拒绝（数据库比它支持的新）并退出，数据库没被改动。旧版程序可以用 `git worktree add --detach <路径> <上一个版本的 tag>` 后构建 |
| B5 | 回归 | `$R/upgrade` 没有官方登录，跳过真实消息；改为在 `$R/real` 里核对迁移后的老团队能正常发消息（`$R/real` 也是从较旧 schema 迁移上来的） | 老团队、老成员正常回复；没选模型的成员跟随默认模型 |
| B6 | 回归 | 从上一个版本的 **MSI** 升级到候选版本的 MSI（需要先装旧版） | 保留安装目录和数据；快捷方式、版本号更新；不丢用户数据 |
