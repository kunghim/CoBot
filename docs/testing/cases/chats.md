# 聊天（无项目会话）与统一归档

聊天是不绑定项目的单人会话，和「团队」是并列的两种模式，由顶部右侧的「聊天 / 团队」切换；新用户默认落在聊天。
每个聊天有自己的托管目录，用户产物（如工具生成的文件）写在那里。聊天用量不计入团队预算统计。
真实 Codex 的用例在 `$R/real` 上做。

| ID | 层 | 步骤 | 期望 |
| --- | --- | --- | --- |
| CH-1 | 冒烟 | 新用户（空数据根）打开应用 | 落在聊天；只有一句按本地时间的问候（清晨、上午、中午、下午、晚间、深夜），没有欢迎图形和动画；输入框占位为「发送消息」；首发前可以选模型、思考强度和权限 |
| CH-2 | 冒烟 | 真实 Codex：发第一条消息，让它记住一个短语；再发第二条问这个短语 | 流式回复正常、Markdown 渲染正常；第二轮准确回忆（同一线程）；首发成功后输入框回到底部 |
| CH-3 | 回归 | 让聊天调用一个原生工具，在当前聊天的托管目录生成一个文件 | 工具调用在「过程」里按一个整体展示，不重复显示结束语；文件出现在该聊天的托管目录，内容与要求一致 |
| CH-4 | 回归 | 正常停止核心并用同一数据根重启，回到该聊天再发一条 | 历史消息还在；恢复到原线程，仍能准确回忆短语；未知状态的上一轮不会被重放 |
| CH-5 | 回归 | 顶部切换「聊天 / 团队」，收起侧栏后再切换 | 两种模式各自的侧栏内容正确；收起列表侧栏后切换按钮随侧栏一起收起（先展开再切换）；刷新后保持上次的模式 |
| CH-6 | 回归 | 侧栏里一个聊天的菜单：置顶、改名、移至分区、打开文件夹、归档、删除 | 菜单项齐全，方向键可操作、逐级 Esc 关闭、窄窗口下子菜单不越界；各动作生效；删除聊天保留产物目录 |
| CH-7 | 回归 | 分区：新建、重命名、删除，切换「最近更新 / 手动排序」和「按分区 / 合并显示」，刷新 | 分区只影响侧栏归类，不改变聊天的目录、文件或原生线程；排序刷新后保持；删除分区时里面的聊天保留 |
| CH-8 | 回归 | 设置 → 已归档：在「聊天 / 团队」之间切换类型；恢复一个聊天并继续对话 | 聊天与团队的归档列表分开；团队的搜索、排序、恢复、批量删除仍可用；恢复后续聊在同一线程（真实 Codex 回忆之前的短语） |
| CH-9 | 回归 | 聊天运行中点停止；再制造一次发送失败 | 停止后输入框恢复，停止意图持久化；失败时显示可理解的原因，不显示原始 JSON |
| CH-10 | 回归 | 聊天里触发原生审批和原生提问 | 审批卡、提问在聊天里出现并可决定；批准或拒绝后行为与卡片一致 |
| CH-11 | 回归 | 四套主题的深浅色；窗口宽 760 和 1440 | 无横向溢出、无裸露翻译键；输入框与团队输入框大小和位置一致 |
| CH-12 | 回归 | 标题栏搜索框输入一个只出现在某聊天消息里的词、一个只出现在某团队成员消息里的词；方向键选择后回车；再搜一个只出现在已归档聊天里的词 | 结果分组限量展示，不一次性展开全部；选中聊天跳到该聊天，选中成员跳到团队视图并选中该成员；归档与已删除的会话不出现在结果里；macOS 非全屏时搜索框在系统按钮预留行之下，不与红绿灯重叠 |
