# 启动、引擎检测、首次使用

每条用例用一个新的空数据根 `$R/fresh-<用例名>`（`$R` 的含义见 [操作指南](../guide.md#3-数据根)）。

| ID | 层 | 步骤 | 期望 |
| --- | --- | --- | --- |
| C1 | 回归 | **找不到引擎**：启动核心时，把这个进程的 PATH 去掉 Codex 所在目录（只对这一个进程生效，不改系统设置） | 界面明确说找不到 Codex、需要什么版本、怎么处理；其他页面可用，不崩溃 |
| C2 | 回归 | **版本过低**：在 `.tmp` 里放一个假的 `codex` 脚本，只输出 `codex-cli 0.100.0`，用设置接口的 `enginePath` 指向它 | 明确指出版本过低和最低版本 |
| C3 | 冒烟 | **正常找到**：默认 PATH 启动 | 引擎状态显示本机 Codex 版本；`$R/fresh-*/engines/codex/home` 被创建；`~/.codex` 的文件清单与哈希前后一致（修改时间不可靠） |
| C4 | 回归 | **官方登录**：在设置页点登录，**由用户在浏览器里完成登录**，智能体不输入密码 | 登录成功；登录文件只出现在这个数据根里 |
| C5 | 回归 | **只用 API key**：另一个空数据根，不登录官方账号；设置页添加网关，key 请用户填，或改用 `$R/gw` 的副本 | 能建团队，能跑通一轮 |
| ST-1 | 冒烟 | **停止与重启**：`POST /internal/v1/service/stop`（需 `X-Instance-Secret`）正常停止，再用同一数据根启动 | 停止返回 202，进程干净退出，没有残留的 cobot、codex 进程；重启后引擎重新自检为 ready，登录仍有效，团队、成员、消息历史、设置都保留 |
| ST-2 | 回归 | **同根重复启动**：核心在运行时，用同一数据根再启动一个 | 被拒绝并退出（退出码 3），报告已在运行的实例，不会出现第二个调度器 |
