# 头像库与头像

## 头像库是怎么工作的

- 头像库不在安装包里。核心启动时从 `https://raw.githubusercontent.com/kunghim/CoBot/main/assets/avatars/index.json` 下载，缓存到数据根的 `assets/avatars/`（实现：`internal/avatars/catalog.go`）。
- 目前只有一个系列「团子」（`dango`），带 sha256 和大小校验。
- 下载失败时保留已有缓存并记录原因；从没下载成功过时，界面用内置兜底头像（`frontend/src/features/avatars/fallback.svg`）。
- 设置页「头像库」卡片显示上次检查时间和错误，可手动「检查更新」。接口：`GET /api/v1/avatars/catalog`、`POST /api/v1/avatars/catalog/sync`。
- 下载地址可在数据根的 `config.json` 用 `assetsBaseUrl` 替换。只接受 https，测试可以用回环地址的 http。
- 角色可以设置头像；成员默认跟随角色，可以覆盖，也可以上传本地图片。
- 发布前要确认 `main` 上已经有 `assets/avatars/`：默认地址指向 `main`，候选版本合并前它可能还没有新内容。

| ID | 层 | 步骤 | 期望 |
| --- | --- | --- | --- |
| AV-1 | 冒烟 | **首次下载**：新的空数据根，正常网络启动；记录下载用时 | 几秒内设置页「头像库」显示「团子」和检查时间，没有错误；`assets/avatars/` 有 `index.json` 和系列文件；角色和成员显示团子头像而不是兜底图；不用刷新页面就更新 |
| AV-2 | 回归 | 在 AV-1 上点「检查更新」 | 没有新版本时不报错，检查时间更新，头像不闪烁、不丢失 |
| AV-3 | 回归 | **网络不通、没有缓存**：新的空数据根，`config.json` 设 `"assetsBaseUrl": "http://127.0.0.1:1/"`（没人监听） | 核心正常启动，启动不被下载卡住；界面全部用兜底头像；设置页显示简短的失败原因；其他功能正常 |
| AV-4 | 回归 | **网络不通、有缓存**：复制 AV-1 的数据根，改成 AV-3 的地址后启动，并手动检查一次 | 头像仍然是团子（用缓存）；显示失败原因；缓存文件没被删改 |
| AV-5 | 回归 | **本地镜像内容异常**：在 `.tmp` 里用 `python -m http.server --bind 127.0.0.1` 起一个镜像，目录结构同 `assets/`。分三次改：系列文件改一个字节（sha 不符）；`schemaVersion` 改成 2；`index.json` 不是合法 JSON | 三种都保留原缓存、报出原因、不误读；界面头像不变 |
| AV-6 | 回归 | **本地镜像新版本**：把 dango 的 `version` 加 1，并同步正确的 sha256 和 size，然后手动检查 | 下载新版本；页面不刷新也会重绘头像（`avatars.updated` 事件） |
| AV-7 | 回归 | 在角色库给「测试工程师」换一个团子头像 | 所有跟随角色的测试工程师成员都变；已覆盖头像的成员不变 |
| AV-8 | 回归 | 给一个成员单独选头像，再改回「跟随角色」 | 覆盖立即生效；恢复后显示角色头像；重启核心后都保持 |
| AV-9 | 回归 | 给成员上传一张本地 PNG 并裁剪；再换回团子 | 上传的图片显示正确；不再使用的上传文件在清理时被删除，正在用的不删 |
| AV-10 | 回归 | `assetsBaseUrl` 设成非回环的 http 地址 | 启动日志有「assetsBaseUrl ignored」警告，回退到默认地址并下载成功 |
| AV-11 | 回归 | 在升级用的数据根上（见 [数据存储与升级](upgrade.md) B1） | 头像库能下载；老成员原有的头像设置保留 |
| AV-12 | 回归 | 用打包产物（ZIP 里的程序）在新数据根上 | 头像库下载成功（发布版用的也是默认地址） |
| AV-13 | 回归 | 观察：不走代理时访问 `raw.githubusercontent.com` 的情况 | 只记录：访问受限的网络下下载可能失败，此时界面是否仍然可用、提示是否清楚。是否写进发布说明由用户决定 |
