# CoBot 首版修复计划

- 日期：2026-10-15；修复起点：`f290144`，产品审查基准：`fd2a15f`。
- 输入：[独立审查报告](首版审查报告-2026-10-15.md)、[94 项验收复核](首版验收复核-2026-10-15.md)。
- 目标：修复 R01～R25，补齐已承诺的首版交付缺口，使 Windows 本机 Web + 真实 Go 核心 + 真实 Codex 达到可试用及两次自举标准。

## 1. 执行边界与原则

沿用 Go、React、Wails、SQLite 和一个共享核心；在现有模块内修复，不重建架构，不增加云服务、Git 执行器或通用工作流平台。CoBot 管任务/消息/状态，外部 Agent 执行文件、命令和 Git。

25 项均纳入本轮，不把 P2 默认为延期。桌面 R23 修复静态接线并编译检查；Windows/macOS 原生运行和安装仍可标待测，不阻塞 Web。正常使用路径先修，异常恢复保持明确的能力边界。

每组先把审查反例改成正式回归测试，再修改实现。原 `.tmp` 诊断测试中“成功证明异常”的断言必须反转成正确行为，不能原样把 PASS 计作修复。测试使用明确的临时数据根，不接触生产 profile 或日常 Codex 凭据/数据库/会话。

按下列阶段顺序执行。每阶段允许多个小提交，提交前列出具体路径，提交信息和修复记录注明 R 编号；不将半成品凑成一次大提交。源码接口变更同步契约、客户端和 fake，不通过放宽 fake 掩盖真实协议问题。

## 2. 分阶段实施与验收

### F0：保存基线、建立修复台账

**工作**：记录起点与已有反例；更正 README 中“已通过全部真实 Web 验收”的不实状态，更新 AGENTS 的旧阶段说明。创建修复记录，以 R 编号关联提交、回归、真实验证及剩余事项。

**完成条件**：25 项都可追踪；当前状态和后续计划清楚；原审查基准与原始结论没有被改写。

### F1：接通官方登录、模型与页面授权

**覆盖 R01、R02、R03、R14、R25。**

- 按本机目标版本协议定义登录结果、账号类型、模型页和中断参数。登录协调器保存当前 loginId 和进行中状态，向页面提供官方 authUrl；页面显示可点击授权入口，不依赖异步窗口自动打开。重复点击复用当前登录流程，取消传入对应 loginId，完成/取消/失败后清理状态并使账号投影缓存失效。
- model/list 读取真实 data 和 nextCursor，映射为现有产品模型字段；读取全部有效页后提供模型选择，正常空列表与协议错误分开表达。
- InterruptTurn 显式接收 threadId + turnId，用户停止、链停止、退出路径统一传递精确运行身份；已结束/已更换 turn 不得误停后继。
- bootstrap 兑换不依赖旧页面会话有效，但保留一次性秘密、有效期、Origin 和用途检查；业务路由仍严格鉴权。为每个稳定 profileInstanceId 使用独立页面/CSRF cookie 名，客户端从启动/状态元数据取得对应名称，避免同主机不同端口的开发、生产和测试实例互相覆盖。
- 把 Vite configureServer 放入真正插件；配置文件纳入检查。开发脚本正确发现/复用既有服务，不删除运行中实例的发现文件；只关闭自己启动的资源，正常退出走受管收尾。

**接口变化**：登录状态/结果有明确 DTO；中断签名携带 turnId；页面会话启动元数据包含非秘密的 cookie 名称；OpenAPI 和前端调用同时更新。一次性秘密不进幂等日志。

**验收**：真实浏览器完成新授权、过期后新链接、服务正常重启重新授权、两个隔离 profile 并存；真实 Codex 登录/取消/登出投影正确，模型列表与引擎一致，真实目标 turn 可停止且不影响其他成员。涉及账号交互时仅等待用户完成官方登录，其余工作继续。

### F2：稳定执行、协作凭据与恢复边界

**覆盖 R04、R05、R08、R09、R12、R22。**

- 19 个 MCP 工具逐一提供真实参数 schema：字段、必填项、约束、枚举和说明；身份与 sourceRun 由宿主绑定。用真实 tools/list 验证定义，参数校验由服务端继续执行。
- 将恢复 thread 改为显式传递本轮 ThreadSpec，包括 cwd、模型/权限和桥配置。每轮激活会话时建立对应的受管凭据，绑定成员、团队、engineEpoch 和来源 Run；有效活动 Run 可续期，闲置/结束/撤销后的令牌不能无限延续。核心重启后重新签发和重配桥，不复用旧内存令牌。
- 服务器在写工具入口核对来源 Run、当前引擎代际与合法活动状态；拒绝闲置、未知或过期前驱执行的写调用。来源 Run 关联在启动回执落库前也必须明确，不能丢掉启动期间的合法工具调用。
- 起始回执只推进允许的旧状态，不覆盖 completed/failed/interrupted/waiting_approval 等更晚事实；通知与回执按身份关联，重复通知幂等。停止派发与调度退出均遵守 context 截止时间，模型/RPC 等待不占状态事务，也不长时间挡住其他成员派发。
- 改绑先暂停目标团队新派发，核验无活动/未知执行；协调关闭旧 runtime、更新目录绑定，并用正确 cwd/会话配置恢复。失败留下明确可重试状态，不在旧 cwd 继续执行，也不依赖一个跨网络长 SQL 事务。
- 恢复动作先核对旧执行终结证据。当前连接的精确终态或可靠受管终止结果可作为事实；单凭数据库改状态、PID 不存在或 thread 可 resume 均不算。无法确认时保持 unknown，禁用会启动新执行的动作并解释原因；正常退出重启仍需可继续使用。

**接口/数据变化**：ResumeThread 接收明确恢复配置；桥凭据增加宿主 Run 关联，令牌值仍只在受管内存/通道中；恢复卡可表达真实可用/禁用选项及原因。只在现有存储确有缺失时新增迁移，不回改 00001～00007。

**验收**：真实 MCP 调用成功；跨短 TTL、正常服务重启后同 Bot 可继续调用；旧凭据/无活动 Run 写操作被拒绝。覆盖启动回执/完成/审批通知的不同顺序，后续队列不被假 running 卡住。改绑后产物出现在新目录。受控恢复测试证明未知旧执行没有结束前不会产生重复 turn。

### F3：修正任务、审批与写入原子性

**覆盖 R06、R07、R10、R11、R13、R19、R20、R21。**

- HTTP/MCP 写动作共享应用层的事务内幂等实现。幂等键按身份+动作限定，规范化正文包含目标资源；幂等记录、业务变更和待投递结果同事务提交，禁止“业务先完成、再另事务补幂等账”。必要的内部 tx 方法复用现有 store，不引入通用事务框架。
- POST/PATCH 和 DELETE 的 requestId/版本要求按现有开发方案落实；前端一次用户操作生成稳定请求 ID，重试复用。创建团队的文件准备继续分阶段，重复请求返回同一预留实体和当前状态；外部 RPC/文件操作不放进数据库事务。未知外部副作用不盲目重放。
- 取消任务与相关未送投递取消同事务，领取派发前再次核验任务/负责人/状态；已运行任务的取消不伪称已撤回文件操作。
- 建立明确任务转换：todo→doing/cancelled，doing→review/cancelled，review→doing/done/cancelled；done 仅通过证据确认入口，done/cancelled 不允许通用修改重新激活。未知枚举拒绝，既有异常数据不静默改成可执行状态。
- 有 taskId 的 open Question 阻塞该任务相关自动派发；无 taskId 时阻塞该成员自动推进。用户直接发送新消息不自动当作问题答案，也不解除原等待；显式回答以 questionId 原子关联答案消息和投递。删除成员/团队及归档普查纳入相关待处理事项，并在变更事务中复核。
- 合并申请绑定 candidateRef、targetRef、executionDirectory、任务 revision 及相符证据 ID/候选引用；决定时再次核对，变化后旧卡不能授权新版本。CoBot 核验登记事实，真实 Git 状态和操作仍由外部 Agent 负责。
- 非原生审批的批准/拒绝生成持久结果通知和唯一投递，携带原请求、决定和候选身份；保持对应任务/因果链门禁，不顺带放开其他工作。重试和重启后不会丢反馈或重复创建成员/执行。

**数据变化**：必要时给投递补明确任务/来源关联，避免复用 run_id 表达不同对象；补幂等唯一约束和审批绑定字段。新增 goose 迁移先做一致性备份，验证已有团队、任务、消息、决定可升级；不改旧迁移，不清空用户数据。

**验收**：取消后不启动任务；相关问题未答不自动推进、答后恢复；待处理事项不允许删除成员。串行/并行/丢响应重试只产生一个资源，换目标或正文冲突；无效版本返回明确错误。合并批准/拒绝送达原申请者，候选或证据变化使旧批准无效。

### F4：补齐共用前端与可操作路径

**覆盖 R15、R16、R17、R18、R23、R24。**

- 工作面板、会话审批栈、query key 与 API 参数统一带当前视图范围：队长全团队，成员自身。由服务端过滤，切成员清掉上一人的详情/错误状态。
- 草稿按 botId 在页面生命周期内独立保存；切换成员/团队不串用，发送始终使用该会话的草稿。其他临时动作状态随会话切换正确重置。
- 审批历史只收有实际决定的记录，保留后来失效事实；按处理时间+ID 稳定倒序，完整显示原选项、选择、请求者、理由、申请/处理时间与入口，保持只读。
- 加入手动增员、重建标记、目录改绑入口；按当前团队状态显示实际可用动作和冲突原因，不堆新增设置页。后端失败不被成功提示掩盖。
- 共用 API 客户端在开始任何查询前完成平台初始化：Web 使用同源地址，桌面使用原生 handoff endpoint。所有 API、SSE、授权续期共用该地址；Bearer 仅保存在内存中。
- 补稳定游标分页，默认 50、最多 100，处理时间相同的 ID 次序。会话可加载更早内容；其他受截断列表有继续加载入口，不能以 nextCursor 恒空隐藏已存事实。客户端消费生成的 wire DTO 或显式适配，避免新增第三套类型。

**验收**：真实 Go 核心浏览器验证成员范围、草稿切换、目录恢复和增员；历史超过一页可完整读取、无漏项/重复。覆盖三卡审批、zh/en、320px、键盘及错误路径。桌面 endpoint 做受控 bridge/不同 origin 的集成检查与静态编译，原生运行单列待测。

### F5：完整回归、真实自举与独立复审

1. 复跑 Go/前端/契约/浏览器检查，执行新增反例；并发敏感路径在工具支持时补 race 检查，不能因 Windows 工具条件缺失冒充已运行。
2. 验证首次构建与独立发行物、旧业务库升级及备份恢复；开发脚本包含真实 Vite 授权，验收脚本不依赖已有 dist 或作者机器路径。
3. 通过产品入口完成真实团队协作：文件读写、多成员并行、队列/取消/停止、真实产物允许/拒绝、任务证据、合并结果反馈、风险评估、页面断流及正常服务重启。记录具体模型版本、profile、任务/产物和实际结果，隐藏凭据。
4. 核对目标 Codex 的实际 hook 支持和接线，验证声明覆盖的工具路径；无法覆盖的能力如实呈现，不将直接调用 hook 适配器当作真实接线。若要求与实际支持矛盾，报告具体差异，不能修改验收标准掩盖。
5. 建立可用的 CoBot 开发实例，让它组织并完成一项受控 CoBot 改进（任务、实现、测试、独立审查、人工授权交付均有记录）；升级后再完成下一项，形成 K01/K02 两次闭环。任务从仍需完成的真实改进/回归中选择，不制造无意义改动或未经授权修改用户其他项目。
6. 完成全量自审后，再启用三个新的独立只读子 Agent，按功能/架构、可靠性/权限、前端/交付复审；主审修复后原方向复核，重大项不能仅由实现者自己关闭。
7. 更新全部 94 项子场景证据，补英文入门/贡献说明、升级和运行说明。最终支持声明绑定实际验收 commit；未测的原生平台继续待测，不公开发布或擅定许可证。

**完成条件**：25 项均有关闭证据；Web P1 清零，P2 完成或获得明确范围决定；真实模型及两次自举完成；独立复审没有未解决重大项。Git 工作区干净，阶段提交可追踪。用户只需在必要时完成官方账号登录及既定人工审批，不需要配合重建环境或重新提供前置验证。
