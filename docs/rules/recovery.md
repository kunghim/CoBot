# 重启、审批与租约规则

触发：改 `internal/app/recovery.go`、`approval*.go`、`lease.go`、`idempotency.go`。

- 重启后不接管任何执行：进程还活着、线程能恢复，都不能证明 CoBot 仍控制着它。未完成的工作交给恢复卡由用户决定。
- 副作用是否已经生效不确定时，标为未知交给用户，不静默重试。
- 审批绑定在发起它的连接上；连接断开后旧审批不能再回应，走恢复卡。Codex 不再等待的请求会自动关闭对应卡片。
- MCP elicitation（`mcpServer/elicitation/request`）走原生工具卡：表单和 URL 认证都是等用户决定的卡，接受时把表单值放进协议的 `content` 回给引擎，拒绝回 `decline`。它的重启行为与审批一致：卡片留到连接恢复或按引擎响应关闭。
- 同一个幂等键必须带相同参数，参数不同按冲突处理。
- 租约过期、缺失或损坏时，有副作用的工具明确拒绝。
- 单张坏卡只报告，不能让启动失败。
- 审批只有三类：原生工具（`native_tool`）、协作链超限（`chain`）、中断恢复（`recovery`）。新增类别前先和用户确认。

做完：`go test ./internal/app/... ./tests/integration/...` 通过；涉及重启时在临时数据根上实际重启一次核心验证。
