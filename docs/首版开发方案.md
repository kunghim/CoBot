## 1. 接手规则与完成定义

### 1.1 先读什么，如何处理旧文档

本次 Windows 编码入口是已有的 `E:\Project\GitHub\CoBot`，仅使用这一段路径；不要拼接重复路径，不执行 clone，不在该目录再生成 CoBot/CoBot。所有下列相对路径相对此仓库根。macOS 使用它实际的 CoBot checkout，不复制 Windows 路径。

1. 先读本文件，再读目录架构、验收清单和界面布局；按开发模块补读需求 R01～R17。
2. 最新用户明确决定优先。本文件将旧文档中未定的常规细节收敛为实施默认；不能因为旧 Q 表写“待讨论”就重新询问已决定事项。
3. 需求中已确认但本文件未重述的功能继续保留。不能将记忆、轮次控制、用量、交接、恢复等删成未来功能。
4. 历史方案中的技术候选和完整小验证清单不是新的开发前置条件。桌面通信、私有登录、多团队共存由用户确认已处理，不再独立做 spike，不再次修复原生 Codex 环境。
5. 核对当前 git 状态，保留别的会话改动；每次只提交本任务具体路径，不做 reset/stash 或批量暂存。旧实验、报告和原始会话资料不清理、不改写成新实测。

截至本方案落档，仓库有文档、HTML 原型及 Node 接入实验，没有 Go 服务或前端产品工程。按里程碑建立工程；不是续写一个已经完成的产品。

### 1.2 产品与首版边界

CoBot 是通用多 Agent 协同应用，编程只是首个场景。Go 核心整理角色、上下文、任务、消息、审批、记忆和状态；外部 Codex 执行模型/工具循环、文件、命令和 Git。禁止在 CoBot 中重写 shell、Git 管理器或 Agent 工具循环。

首版必须提供 Windows/macOS 桌面与本机 Web；只绑定 loopback，不建设云业务或远程业务服务。开发与生产隔离，开发测试可以只开开发服务。

不做群聊、Claude 实接、定时任务、开机自启、插件市场、跨团队共享、办公角色模板、独立成果库、自动更新、角色可视化编辑或公开遥测。

完成标准：用户真实创建团队，经队长拆任务、成员实现、测试审查、用户授权，由外部 Agent 交付一项 CoBot 功能；升级后的 CoBot 可以继续下一项工作。模拟聊天、模拟 MCP 回执、能打开窗口均不能替代此标准。

## 2. 技术栈与工程执行方式

| 部分 | 实施选择 | 禁止替代 |
| --- | --- | --- |
| 后端 | Go，`net/http`、`context`、`log/slog` | 不换语言，不引微服务/Redis/DI 框架 |
| 前端 | React、TypeScript、Vite；npm 锁文件 | 不做两套桌面/Web UI，不引 Next/SSR |
| 路由/服务状态 | React Router Declarative Mode、TanStack Query | 不用 Framework Mode，不引重复 loader 数据层 |
| UI | Tailwind CSS、按需 Radix、Lucide | 不批量搬大型模板，不提前摆未来功能 |
| 桌面 | Wails v2 稳定线 | 不擅换 v3 Beta/Tauri/Electron |
| 数据 | SQLite、`database/sql`、modernc | 不用 ORM，不读取或写入 Codex 数据库 |
| 迁移 | goose Provider、嵌入 SQL | 不自写 runner，不自动 down |
| 协作工具 | 官方 MCP Go SDK 的兼容稳定版本、stdio 桥 | 不解析自然语言或特殊代码块作为协议 |
| 事件 | HTTP JSON + fetch SSE | 不通过 Wails 资产服务器代理业务流，不换 WebSocket |
| 国际化 | i18next/react-i18next/Intl，zh-CN/en | 不将中文状态写入数据库，不翻译用户原话 |

Go module 为 `github.com/kunghim/CoBot`。M1 选择相互兼容的受支持稳定版本，提交 go.mod/go.sum/package-lock 与构建工具记录；不使用预发布依赖凑接口，不在后续里程碑无理由升级版本。Codex 二进制可为当前已验证版本，不能把它的 alpha 版本号误当成所有依赖也可选 alpha。

构建和启动要求见目录架构。最终用户不需要 Node.js、Go 或数据库服务器；开发者需要构建工具。Codex 外部安装和官方账号由用户提供，缺失时报告，不自动安装。

测试使用 Go、Vitest、Playwright。日常 CI 使用假适配器，不消耗账号；真实验收单独显式执行，报告实际账号调用结果，不用 mock 替代。

## 3. 功能要求与确定的默认行为

### 3.1 环境、引擎与登录（REQ-01；验收 A01～A08、C01～C05）

- 默认服务模式为开发；生产必须显式选择 `--profile production`。桌面开发构建用 development，发行构建用 production；两者用同一个核心实现。
- `--data-root` 可显式覆盖当前profile的数据位置，供测试/独立运行；测试只用 `.tmp/test-runs/{runId}/profile`，不得使用真实 `~/.cobot`。自定义根保存profile/instance身份，冲突拒绝打开。data-root不是团队cwd。
- 开发根 `~/.cobot-dev`、生产根 `~/.cobot`；数据库、凭据、引擎状态、缓存、日志、锁、WebView 数据分离。不得更改全局环境变量。
- 环境级单实例锁持有到退出。重复启动连接/提示已存在，不能再开第二个调度器。只关闭明确属于自己的资源。
- `profileInstanceId`首次建库产生并持久保存；team.json的instanceId指这个稳定值。`serviceEpoch`每次核心启动改变，`engineEpoch`每次app-server重建改变，二者用于连接/租约/请求代际，不能写作团队永久身份。恢复备份需显式处理事件游标，不假装旧服务仍在线。
- 真实定位 Codex，记录版本和所用协议能力。当前 Windows 恢复证据见[恢复与共存记录](验证/2026-10-14-Windows恢复与共存验证.md)：明确选择已支持的沙箱，不回退旧初始化路径或完全访问模式。
- 编程默认 workspaceWrite，启动cwd及可写根以团队/已授权任务位置为准，审批保持用户路由。Windows目标版本支持时对子进程明确 `windows.sandbox=mxc`，不只依赖偏好开关；macOS用其实际支持的受限策略。无法表达时返回能力错误，不自动改原生配置或降到无沙箱。
- `CODEX_HOME`、SQLite 状态根在同环境私有引擎目录；使用已有证据对应的显式配置。不可复制/链接原生 auth.json 或整份 config。
- 用户已接受 CoBot 私有环境独立官方登录。统一登录协调器管理浏览器授权、取消、完成和登出；团队不并行发起登录。凭据由 Codex 管，不落到业务库或项目资源中。
- 默认模型来自该私有环境的有效配置/引擎列表，设置可选择可用模型。不写死作者账号专属模型，不将“提供方名字 custom”直接解释为第三方服务。
- 登录过期或能力不足时清晰显示操作入口；禁止自动复用内部 `chatgptAuthTokens` 接口。
- 更换引擎路径或登出要求无活动/未知Run和待审批，冲突返回409，不默默杀任务。模型修改只影响新轮，已有Run保留原模型快照。账号API不输出token。

### 3.2 团队、目录与成员（REQ-02；B01～B09）

- 创建只填名称、必选目录、可选初始角色；自动产生队长。默认最多 6 个 Bot，包含队长，可在高级设置调整。可重复引入同角色，实例身份不同，显示名可区分。
- 五种专业角色：产品经理、前端开发、后端开发、测试工程师、代码审查；队长不是专业角色之一。每 Bot 仅属于一个团队。
- 一个目录只绑定一个团队，拒绝嵌套。真实路径规范化处理大小写、链接/联接和路径分隔边界，不能用不带目录边界的字符串前缀判断。
- 目录绑定以数据库为准。`.cobot/team.json` 是识别信息，不是另一套事实源。删除 `.cobot` 不可绕过绑定；提供重建入口并报告资源损失。
- 未知标记/复制标记不自动接管；给用户“接管为新团队/取消”。搬家必须显式重新绑定，核对冲突。目录丢失时暂停相关派发，不回退公共根。
- 创建分阶段：先原子预留绑定与成员，再准备标记和资源；成功后激活。准备失败保持可重试状态，不启动半建团队，也不删除用户原有 `.cobot`。
- Git 目录通过 `git rev-parse --git-path info/exclude` 等真实定位，仅幂等添加 `.cobot/` 本地排除，兼容 `.git` 为文件；不修改共享 ignore、不提交、不初始化普通目录 Git。
- 队长招募必须经用户批准，批准之前不创建可运行成员。用户手动添加无需第二次审批；名单更新在下一轮带入，不唤醒空闲 Bot 只为广播名单。
- 有未完成任务、未结束交接、在途执行或待处理请求时禁止删除 Bot。团队归档前无运行/待处理审批/在途交接；归档暂停派发、保留任务、可恢复。删除要求没有未完成工作，软删除应用记录并解除绑定，保留审计与用户文件。
- 开发/生产使用不同团队工作位置；如果同目录带另一环境的标记，不自动覆盖。可由用户/外部 Agent 准备独立工作位置，不由 CoBot 自动创建 worktree。

### 3.3 对话、队列与执行（REQ-03；C06～C10、D01～D08）

- 每团队一个 app-server、每 Bot 一个 thread。Bot/thread 映射持久化；CoBot 消息不等于 provider 历史。重建外部 thread 不删除产品消息。
- 每 Bot 最多一个活动 Run。每团队短状态队列只做状态决策，不等待模型；不同 Bot 同时执行。队列、审批回调和中断不能被长 turn 阻塞。
- 用户可直接与任意 Bot 对话。运行中追加默认 FIFO 排队，不自动 steer/interrupt；界面显示已收下/排队，用户可取消尚未发送项。显式停止当前执行只影响该 Bot。
- 消息先写库，Message 与 Delivery 同事务；返回 accepted 不代表 delivered/completed。模型等待时不持有 SQL 事务。
- 同一客户端 requestId 重试返回原消息；不同内容复用 requestId 返回冲突。领取派发串行，给一次唤醒唯一 dispatchKey。
- turn/start 超时或回执丢失，可能已经执行；保持 unknown 并核对，禁止自动再启动。只有确认未发送的 Delivery 可以续送。
- 终止事件区分 completed/failed/interrupted/unknown。`turn/completed` 名称不直接等于任务完成。运行中不无限缓存所有 RPC/文本。
- 即时文本按消息归属合并，完成后保证最终正文落库；断线可丢中间字符通知，但快照必须恢复已持久正文。
- Bot 状态来自运行事实：空闲、排队、工作中、等待审批、需要输入、中断、待核对。不要用动画或一句回复虚报“正在工作”。
- 首次thread设置角色/目录/真实协作工具；每次派发用 `BuildContext` 带最新团队目录、当前名单、任务标准/依赖/证据、相关未读协作消息、筛选后的记忆及角色版本。不能只在thread创建时带一次，后续依赖旧模型记忆。
- 上下文来自应用查询且按当前身份筛选，审批卡/凭据不入模型。长资料使用有来源的引用和摘要，剩余信息用工具查询，不无限拼接全团队聊天。

### 3.4 任务与结构化协作（REQ-04；E01～E11）

- Task 有 team、唯一 owner、标题、描述、完成标准、状态、父任务、依赖、证据、revision。状态为 todo/doing/review/done/cancelled；blockedReason 是附加标记。
- 用户/队长可以建任务和指派，成员只能提议；成员更新自己的任务。后台检查身份与归属，UI 隐藏按钮不算权限控制。
- 依赖必须同团队、无环。依赖未 done 时不自动启动任务；父任务是组织关系，不自动等于依赖。
- 有效指派为owner创建一次task-assignment Delivery，与指派同事务；依赖未满足则waiting_dependency。前置done后产生/激活唯一投递，不靠模型自行轮询发现任务。已取消/已归档/已换owner的未送投递停止；用户提问不会自动当作任务指派。
- 已完成必须有相符证据；成员 report_completion 进入 review，队长/用户依据证据确认 done。聊天说“完成”不自动改状态。
- offer_transfer 保留旧 owner；目标 accept 时检查 task revision、有效请求和目标资格，事务更换 owner 并通知队长。过期提议失效不抢负责人。
- 接受交接或用户直接换owner时，旧owner在该任务上的Run须已确认结束，否则409。不能在旧执行还可能写文件时启动新owner；接受成功取消旧owner未送任务项并生成新owner唯一投递。
- MCP `send_message`、任务工具、交接、招募、ask_user 和 memory 操作使用宿主绑定身份。from/team 不是模型输入，可选 targetId 必须后台核对。
- MCP stdio 桥只把结构化调用交给核心；stdout 仅 MCP 协议，日志到 stderr。桥不读写业务数据库，不自建投递队列。
- 每个调用保存 idempotencyKey/身份/调用关联；重试不多建任务、不重复计轮。服务不可用时返回失败，不返回“已送达”。
- 用户提问与审批分开：ask_user 返回等待事项，答案通过用户消息投递，不算安全授权。协作记录只读，插话走对应 Bot 会话。
- ask_user 持久化 Question（open/answered/cancelled），工具返回waiting事项ID并要求结束当前工作；不用长阻塞MCP等待用户。当前turn结束后可仍显示需要输入，阻塞对应任务自动派发。回答带questionId，Question决议与新Message/Delivery同事务；不伪造活动Run一直等待。

### 3.5 审批与版本授权（REQ-05；F01～F10）

- 请求统一为 native-tool/collaboration/recruitment/recovery/merge 等类型，原选项快照持久化。安全审批以引擎请求为准，不自行扫描命令文本宣称全面风险识别。
- 队长待审批覆盖全团队，成员只自己的请求，恢复卡只队长。两入口投影同一 request；卡片不投给模型，客观决定可写回相关工作。
- 用户点击时校验 request revision、选项、连接代际、有效性；决策 CAS，写 decision 和待响应记录同事务。
- 决策保存后卡片移除并进入历史，但响应状态单独记录 queued/sent/confirmed/unknown/expired。写入 stdin 不等于被接受，也不等于工具成功；只有明确事实才显示 confirmed。
- 回复只能发给原 connectionEpoch/requestId；新进程不可使用旧请求号。失败不伪装“命令未执行”，不自动重放未知响应。
- “总是允许这个 Bot”只在精确作用域能表达时启用。仅线程级授权需标明有效期，不能顺带扩为团队、另一目录或所有未来命令。不能准确实现时该项禁用并说明；设置提供撤销已有支持规则。
- 等待无自动超时拒绝。无人工决定的失效/取消记动态与内部事件，不放到只展示已处理的审批页；已有人工决定保留历史及后来失效结果。
- 合并审批绑定实际候选标识（如 SHA）、目标与测试/审查证据。授权后由外部 Agent 执行；候选变化需要新确认。原生工具审批与合并确认不是同一个许可。
- 处理入口、操作者、时间、原选项、选择、真实原因均保留。系统自动动作不能写成用户批准。
- 首版“常驻”仅提供引擎支持的当前Bot-thread会话范围，提示有效到thread结束；不新增跨重启持久规则。无对应能力则禁用，不做未经验证的命令解析器。撤销要求无活动/未知Run；无原生撤销接口时结束旧thread、下一次重建，不能仅删CoBot记录就声称撤销引擎授权。
- 合并确认只证明CoBot授权了绑定版本；提示词、Agent回报或UI按钮不证明任意间接Git命令被硬阻断。门禁只限受支持并实际验收的引擎/hook路径，不用CoBot Git执行器补洞。

### 3.6 轮次、记忆与用量（REQ-06；G01～G08）

- 协作链只计算 Bot 间消息/交接造成的实际唤醒，不计算工具调用。默认上限 6；同一 dispatchKey 不重复计数，计轮与派发资格在同一事务确定。
- 最后 `ceil(limit*0.2)` 轮为风险区：6 轮的第 5、6 次唤醒之前评估；已有 6 次唤醒后不能开始第 7 次。链内并发共享计数，不分别各有 6 次。
- 用户消息开新因果链，不能清零仍在运行的旧链。用户批准继续为该链新 epoch，关联的未送消息才可继续；不顺带授权别的链。
- 风险模型沿用同环境 Codex；可配置可用模型，缺省使用有效默认模型。结构化结果 continue/ask/unknown；失败或 unknown 转用户确认，不放行。硬上限不可被模型判断覆盖。
- 风险评估使用独立评估会话与只读/无业务执行工具的配置，不占正在执行成员的 thread；它不是用户可操作的团队成员，不增加业务唤醒计数，用量计账。
- 评估会话存purpose=risk_eval，teamId必有、botId可空；计入团队用量，不能把系统评估伪造成第7个成员或让它获得协作写工具。
- 协作确认可用“下一步将继续推进当前任务，请确认是否按当前方向继续”，保存真实内部触发原因但不虚构安全风险。停止只取消对应链未送项并中断其活动执行。
- 记忆按 Bot/Team 隔离，存正文、来源 run/task、时间和删除 tombstone；只存方法偏好，不自动保存任务证据、秘密或整份代码。每轮结束可要求同一 Bot 用结构化 memory 工具记录新增事实，不另建每轮额外推理。
- 检索先归属过滤，再轻量文本相关性；默认最多 10 条、总计 6000 字符，超限截断并提供来源。删除后立即不检索；同来源与相同归一化正文不得自动再建。
- 账本按 engineEpoch/thread/turn/usage 语义去重。累积 usage 更新保存最高/最新完整快照，不把每条累积值反复相加。输入+输出总量不再叠加已包含的 cached input。
- 默认预算不设限；高级设置可设 Bot/团队 token 上限，没有最低预算规则。已结束结算达到上限后禁止新轮，已启动允许结束；并发可能超阈值，不承诺精确计费硬上限。评估会话也计入团队。
- usage 缺失记 unknown。预算启用时无法判定剩余额度则暂停相关新轮并说明，用户可取消预算限制或修正设置；不将 token 显示为订阅余额、金额。

### 3.7 恢复与退出（REQ-07；H01～H09）

- 正常退出停新派发，保存已接收事实，请求中断，有界等待；默认退出等待 10 秒后终止自己管理的残留进程，并记录中断/未知。不能杀非自身拥有的服务。
- 中断不删除任务、不回滚文件、不自动写 done。先确认旧 Run 结束再允许该 Bot 下一轮。
- 意外崩溃保留“不停但降级”方向：本地租约与明确拒绝 hook、事件转发失败落盘。租约默认每 2 秒更新、10 秒有效；陌生代际、过期、缺失或损坏返回明确拒绝受覆盖的副作用工具。
- 必须适配真实引擎 hook 输入输出、信任与覆盖，不编造未知 hook 名称或把 MCP 断连当保护。已运行命令、hook 异常/被跳过等不能保证撤销；报告范围，不宣称全面隔离。
- 正常退出的主动停止与崩溃策略分开；不能无条件使用 kill-on-parent-exit 破坏保留执行方向。
- 事件文件带 eventId/实例与连接代际/Bot/Run/调用关联，按允许字段保存脱敏元数据，原子写；实时与导入同幂等键。导入成功再清理，损坏文件隔离。
- 落盘默认总额 20 MB，保留最近 7 天已导入事件；未导入证据不能静默按时间删除，容量不足记 gap 并进入待核对。
- 启动取得锁、迁移、导入，再对账未终结 Run/Approval/Delivery。确认已结束补事实；确认仍运行且恢复事件、审批和中断控制才算接管。PID 活着或 thread resume 不是接管。
- 不支持在途重连时明确 capability 缺失并标待核对，暂停该 Bot 新派发；可提供安全停止已识别残留、确认旧执行结束后重发或放弃。未知进程不自动终止，旧请求不重发。
- 特定版本不能实现降级或必要门禁时，报告真实问题并保留相关完成项为未通过；不扩大权限、不伪造能力、不将问题重新包装成开发前 spike。

### 3.8 UI、认证与国际化（REQ-08；I01～I11）

- 首页面采用既有原型的结构，不另做模板化产品：常驻一级图标导航、可收起团队列表、当前用户会话、可收起工作面板。
- 一级顶部 logo/首页、底部设置；团队列表展开保留 cobot 徽章。首页和列表开关是不同动作。两侧独立图标收起，恢复图标可达，具备 tooltip/aria-label/expanded。
- 右侧五页任务/审批/动态/协作/记忆，无团队页。队长任务审批动态看全团队；成员按自己筛选；协作与记忆始终当前 Bot。切人清详情、保留页签。
- 待审批在输入框上方单卡，显示 `当前位置/总数` 并翻页，不轮播；处理后移除、显示相邻项。没有重复“待你处理 N”“还有一张”“审批记录”按钮或输入框“等你审批”。全局待办入口和成员等待状态可在列表保留。
- 目录仅队长头部集中展示；成员显示所属团队、任务。轮数、风险区、预算、token、内部 `.cobot` 不放日常首页；高级设置有明确入口。
- 设置首版包含语言、Codex 路径/状态/登录、默认及评估模型、成员上限、轮次上限、预算与可支持授权撤销。不是空白占位；用量无独立大页面。
- 桌面直接 fetch loopback API/SSE，Wails 绑定仅窗口/目录选择/启动握手。桥返回一次性 secret，兑换内存 Bearer；到期通过桥续期，credentials omit。
- 浏览器同源 HttpOnly Cookie+SameSite Strict+CSRF；一次性链接秘密放片段，兑换后清 URL。Bearer、Cookie 和 MCP 凭据用途分开，不能互换；日志不记录。
- bootstrap 默认 60 秒且一次使用；桌面 Bearer 30 分钟，到期关闭流、续期后带 cursor 重连。重启服务旧授权全部失效；浏览器重新通过受控启动链接授权。
- 精确 CORS/Host 来源校验；`Origin:null` 只是兼容条件，不是身份。不能允许请求自行注册 Origin，不能 CORS *。
- 所有系统 UI/错误/空状态/确认用 zh-CN/en；机器错误 code+params。模型原话保留，Markdown 禁 raw HTML；链接协议白名单。窄屏列表/面板覆盖式，320px 宽可操作，不承诺 iOS 客户端。
- 浏览器目录选择只给已认证用户枚举可访问目录名称/规范路径，不提供任意文件正文读取/写入；引擎状态根、runtime、data等保留位置不可绑定。目录选择不扩大引擎沙箱权限。
- 桌面接已有服务通过同用户受控runtime凭据取得新bootstrap；instance.json仅定位，不含直接授权secret。Bootstrap等待核心Ready，不先发不可用endpoint；页面续期不调用Codex重新登录。

## 4. 接口和存储的最低契约

### 4.1 公共 API

字符串 ID 使用 UUID；时间 UTC RFC3339；revision 为整数。请求 requestId 与资源 revision 分别处理重复和并发，不互相代替。写入返回资源事实；错误包含 `code/messageKey/params/requestId`，不能返回凭据或整个底层配置。

| 路径（均在 `/api/v1` 下） | 最低职责 |
| --- | --- |
| GET `/status`、GET/PATCH `/settings` | 环境/能力/产品状态，设置；status 不泄露路径秘密 |
| GET `/engine`、GET `/models` | 引擎版本、非秘密登录状态、能力、模型 |
| POST `/auth/login`、POST `/auth/login/cancel`、POST `/auth/logout` | 私有环境官方认证；这是 Codex 登录，不是页面 bootstrap |
| POST `/session/bootstrap` | 启动秘密兑换页面会话；短效、防重放，不进入业务日志 |
| GET `/directories`、POST `/directories/check` | Web 本机目录选择和绑定校验，不能执行任意文件操作 |
| GET/POST `/teams`、GET/PATCH/DELETE `/teams/{id}` | 团队列表/创建/更新/删除 |
| POST `/teams/{id}/archive`、POST `/teams/{id}/restore` | 明确归档与恢复，不靠任意PATCH状态绕过检查 |
| POST `/teams/{id}/directory/rebind`、POST `/teams/{id}/directory/rebuild-marker` | 显式搬家改绑与标记重建，先验证目标冲突 |
| GET/POST `/teams/{id}/bots`、DELETE `/bots/{id}` | 成员与权限管理 |
| GET/POST `/bots/{id}/messages`、POST `/messages/{id}/cancel` | 用户会话与排队消息 |
| GET `/questions`、POST `/questions/{id}/answers` | 独立用户问题列表/答案与关联消息，不借审批许可实现 |
| POST `/runs/{id}/interrupt` | 明确中断目标执行，不影响整个团队 |
| GET/POST `/teams/{id}/tasks`、PATCH `/tasks/{id}` | 任务板、状态、证据与依赖 |
| POST `/tasks/{id}/transfers`、POST `/transfers/{id}/accept` | 两阶段交接 |
| GET `/approvals`、POST `/approvals/{id}/decisions` | pending/history 查询与一次决定；history 不混 pending |
| GET `/bots/{id}/collaboration`、GET `/teams/{id}/activity`、GET `/roles` | 协作记录、动态与用户角色库；按当前范围投影 |
| GET `/bots/{id}/memories`、DELETE `/bots/{id}/memories/{memoryId}` | 当前Bot记忆列表与删除 |
| GET `/authorizations`、POST `/authorizations/{id}/revoke` | 仅支持的当前thread授权与真实撤销结果 |
| GET `/snapshot`、GET `/events?after={cursor}` | 同事务快照游标、fetch SSE；按范围和会话校验 |
| POST `/recoveries/{id}/decisions` | 恢复请求选择，不自动重跑未知执行 |

MCP bridge 使用 `/internal/v1/collaboration` 等独立内部路由和 Bot-scoped 凭据；只有浏览器身份的客户端不能假装 Bot，Bot 凭据不能调用用户审批、设置或删除团队接口。HTTP handler 与 MCP handler 都调用同一应用方法。

Bot桥凭据绑定profile/team/bot/providerSession/engineEpoch。sourceRun由核心当前有效Run解析，不将创建thread时的runId永久写入长寿命MCP进程；无活动Run的写工具拒绝。写入者发来的taskId仍核验owner/同团队，不能凭合法token修改任意对象。权限保证是CoBot接口及真实引擎已支持范围，不宣称抵御同系统账号下任意恶意进程窃取本机材料。

补充字段在对应里程碑写入 OpenAPI，再生成 Go DTO 和 TS 类型。OpenAPI 是公共 wire 契约；domain 不直接成为 JSON DTO，Codex DTO 不泄露到 API。事件协议明确 `seq/type/teamId/botId/resourceId/revision/payload`；持久事件用 seq，瞬时 chunk 明确带 Run/Message 关联而非假装可永久回放。

#### 4.1.1 必须落实的 wire 字段与状态

成功响应为 `{data, requestId}`，错误为 `{error:{code,messageKey,params},requestId}`；不返回原生 stack/token。列表 data 为 `{items,nextCursor}`，默认50条、最多100条，稳定按创建时间加ID排序。scope查询由后台验证，不能只前端过滤。

POST/PATCH业务写请求在body携带UUID `requestId` 作幂等键；更新、决策、交接接受携带 `expectedRevision`。DELETE用 `Idempotency-Key` header及 `If-Match` revision，handler转换为相同应用请求。body和header冲突拒绝，不默默选一个。同幂等键同身份同操作不同正文409；缺少合法版本的状态修改400。GET不要求调用者生成幂等键。secret兑换只验证一次性秘密，不保存秘密到幂等日志。

| 对象 | 最低公共字段/输入 | 状态及约束 |
| --- | --- | --- |
| Team | id/name/directory/profile/leaderId/status/revision；创建name/directory/initialRoleIds/requestId | creating/active/archived/deleted/directory_missing/error；profile服务端确定 |
| Bot | id/teamId/name/roleId/isLeader/status/currentRunId/currentTaskId/revision | 产品状态来自执行事实，caller不能修改teamId/isLeader越权 |
| Message | id/teamId/botId/kind/blocks/createdAt/deliveryStatus/requestId | kind=user/assistant/collaboration/system；用户POST仅提交允许的text/资源引用 |
| Delivery | id/messageId/targetBotId/taskId/chainId/epoch/status | waiting_dependency/queued/dispatching/accepted/cancelled/unknown；accepted不是任务done |
| Run | id/teamId/botId/providerSessionId/providerTurnId/status/startedAt/endedAt | starting/running/waiting_approval/waiting_input/completed/failed/interrupted/unknown；每Bot一个活动Run |
| Task | id/teamId/ownerId/parentId/title/description/acceptanceCriteria/status/dependencyIds/evidence/blockedReason/revision | todo/doing/review/done/cancelled；证据为引用/说明，不以聊天结论代替 |
| Transfer | id/taskId/fromBotId/toBotId/taskRevision/status | offered/accepted/cancelled/stale；接受检查当前owner与revision |
| Approval | id/teamId/requesterBotId/runId/type/summary/reason/options/requestState/decision/responseState/revision | options快照含id/messageKey或安全原文；决定输入optionId/comment/expectedRevision/requestId |
| Memory | id/teamId/botId/content/sourceRunId/sourceTaskId/createdAt/deletedAt | 身份和归属由服务端确定；删除仍保留防重提标记 |
| Question | id/teamId/requesterBotId/taskId/runId/question/options/status/revision | open/answered/cancelled；答案为text加用户Message关联，不是审批decision |
| Recovery | id/teamId/botId/runId/knownFacts/unknownFacts/availableActions/status/revision | pending/resolved；只提供真实可执行action，能力缺失不伪装continue |

HTTP约定：已创建201、消息已持久等待202、普通成功200；非法输入400、未登录401、越权403、不存在404、revision/生命周期冲突409、适配能力缺失422、引擎不可用503。引擎派发结果未知返回已保存的unknown资源，不把它作为可自动重试的通用503。

MCP类型采用SDK schema；原生RPC requestId保留数字/字符串原类型，不能统一转字符串后回复。

#### 4.1.2 MCP最小工具契约

所有工具身份与team来自受管凭据，arguments不接受from/team。所有写工具要求非空 `idempotencyKey`（最多128字符），更新要求expectedRevision；sourceRun由宿主绑定。读工具不要求写幂等键，不把全部角色库暴露给普通成员。结果包含 `status/data/error`，status为ok/accepted/duplicate/waiting/rejected/unavailable；accepted只表示事实已持久。

| 工具 | 参数（除公共字段） | 调用权限/后台动作 |
| --- | --- | --- |
| get_context | 可选taskId | 当前Bot范围上下文/目录/成员/待处理信息，不给审批卡或secret |
| list_tasks / get_task | status或taskId | 同团队授权任务视图，不允许跨团队 |
| list_roles | 无 | 仅队长获取完整内置库；成员无权限 |
| send_message | targetBotId/text/可选taskId | 同团队目标；一次入库与投递，继承源链epoch |
| create_task | title/description/acceptanceCriteria/ownerId/可选parentId/dependencyIds | 仅队长，用户走HTTP；检查owner/依赖并建立一次任务投递 |
| propose_task | title/description/acceptanceCriteria | 成员形成提议消息，队长确认后才建Task |
| assign_task | taskId/ownerId | 仅队长；按安全换owner规则，不能直接跳过交接检查 |
| update_task | taskId/status/blockedReason | owner更新todo/doing/review；done由confirm_task，cancel由队长或用户 |
| submit_evidence | taskId/summary/可选artifactRefs/candidateRef/testResult/reviewResult | owner或队长；记录来源/候选版本，不执行文件操作 |
| report_completion | taskId/evidenceIds | owner提交review，不直接done |
| confirm_task | taskId/evidenceIds | 队长确认有相符证据；用户也可HTTP确认 |
| offer_transfer / accept_transfer | taskId/toBotId/note 或 transferId | owner提议，目标接受；检查修订与旧Run结束 |
| request_member | roleId/reason | 仅队长，建招募Approval，未批不运行 |
| ask_user | question/可选options/taskId | 当前Bot请求输入，建Question并返回waiting |
| request_merge | taskId/candidateRef/targetRef/executionDirectory/evidenceIds | owner或队长，建绑定版本审批，不执行Git |
| remember | content/可选taskId | 当前Bot写方法偏好；sourceRun服务端确定，删除重提规则仍生效 |

合并/测试/证据的Agent回报是有来源的事实，不伪装成CoBot独立执行或验证。工具schema注册、HTTP映射和OpenAPI在相应里程碑一起提交，不能先永久返回固定成功字符串。

#### 4.1.3 状态转换与事件恢复

- Run：starting→running→completed/failed/interrupted；原生等待可进入waiting_approval/waiting_input再恢复running；不确定进入unknown后须核对才能终结。
- Task：todo→doing→review→done；退回修改review→doing，取消由队长/用户；只变Task不会伪造Run终结。
- Approval.requestState：pending→decided或invalidated；已decided保留用户决定，即使后续response过期。response与执行状态分开。
- 每Bot单活动约束覆盖starting/running/waiting/unknown；Question是独立等待标记，不把已completed的Run重新变running。
- snapshot在同一读事务返回实体和当前全局seq。SSE先订阅“有提交”通知，再查询DB中cursor之后事件，之后每次通知再查询，不仅依赖内存事件队列；提交到订阅间不会丢持久事件。
- 按team/bot过滤后的全局seq可跳号，不能把合法过滤跳号当丢事件；游标不匹配实例或已超保留边界才要求新snapshot。客户端应用后推进cursor，重连去重；chunk以Run/Message/offset关联，最终正文以snapshot为准。

### 4.2 数据模型与事务

按实际需要建表：teams/directory_bindings/bots/provider_sessions/messages/deliveries/runs/tasks/task_dependencies/transfers/questions/approvals/approval_decisions/approval_responses/chains/memories/usage/events/recoveries/hook_imports/settings。产物首版可为任务证据 JSON 引用，不单建成果库。不得全库 EAV 或整团队巨型 JSON。

外键、唯一索引和状态约束负责归属与去重；软删除对象保留历史。所有团队对象显式 teamId。目录预留、任务交接、审批决定、消息/outbox、唤醒计轮、usage 去重、恢复导入必须事务执行。外部网络和模型调用在事务之外。

SQLite 首版连接池最大 1 条；保持事务短，不建额外写队列框架。WAL、foreign_keys、busy_timeout=5000ms、synchronous=FULL 确保连接生效。数据库 busy 返回可重试错误，不无界循环。需要扩大读池时作为后续有证据的优化。

单连接事务内只能用tx查询/执行，不能持有tx再调用db方法等待第二条连接；Rows使用完立即关闭，嵌套查询先收集结果再查。events首版不自动清除审计记录，payload只放事实摘要/引用，不逐token或完整环境落库。

迁移用 `sql.Open("sqlite", ...)` 得到同一库连接，再交 goose SQLite 方言 Provider；启动查库版本，高于程序支持版本则拒绝打开业务。升级前用 VACUUM INTO/backup API 保存一致性快照，不能直接拷贝活跃主文件遗漏 WAL。默认保留最近 3 份成功升级前备份；恢复是显式维护操作，不在启动时静默换库。

业务日志默认每文件 10 MB、最多 5 份；console 不输出 auth/header/启动秘密；恢复事件另按REQ-07管理，不受日志轮转删除规则影响。

## 5. 分阶段开发步骤

每阶段先提交对应契约、迁移和测试，再打通实际路径；不能用永久 TODO 或硬编码成功填充验收。新目录按目录架构按需建立，不一次建完所有空包。

### 5.0 阶段验收不是提前要求后续功能

同一验收ID可能有多个平台/子场景，报告逐子项状态。M1先用settings旧库种子测迁移机制，M4/M5才测已有真实Task/Message升级；M1身份中间件用测试principal测用户/Bot隔离，不要求MCP已实现。M1的J01/J03/J04只交付构建链和当前包，不要求正式installer/SBOM全完成。

Windows主开发可连续推进；macOS实际子项由该平台运行后记通过，未测不冒充通过，也不阻塞无关编码阶段。最终首版声明必须覆盖交付的架构/平台；无法取得平台只如实标未测，不临时删掉支持目标。

### M1：可运行产品骨架

1. 建 Go module/前端依赖锁与 CI，建立最小目录、统一应用启动/关闭与开发脚本。
2. 做 profile 路径、锁、实例发现、配置、日志，完成数据库初始化/迁移/备份。
3. 做 API 错误/身份中间件、页面 bootstrap、snapshot/events 最小闭环。
4. 做前端 API 客户端/Query/流管理/i18n、首页导航与设置骨架；空数据用真实空状态，不展示假团队。
5. 接 Wails 只用同一核心/前端，原生目录选择/握手；构建资源链可复现。

交付：独立 Web 和桌面均可启动，设置重启保留，dev/prod 不串库。按5.0完成M1机制子项；可用模拟事件测SSE，但不宣称真实Codex接入完成。

### M2：团队与真实执行

1. 做引擎真实定位、版本适配/私有登录/模型，应用内状态与错误入口。
2. 做目录检查、创建分阶段、成员角色/名单/本地排除；数据库事实驱动 UI。
3. 做团队进程与 Bot/thread、消息队列/Run/RPC 分发、真实流、中断。
4. 做原生审批的一次允许/拒绝、队长与成员卡片同步、送达状态。
5. 验收多 Bot 多团队实际工作、关闭重启与线程映射，沿用户已处理的前提正常集成，不建独立实验。

交付：可真实与成员工作并操作审批；按5.0的M2范围完成。Bot间MCP发送D02留M3，团队删除归档B08/B09留M4，不要求提前实现。没有真实产物不得记通过。

### M3：协作任务闭环与开始自举

1. 做 Go stdio MCP bridge、核心工具注册与身份绑定；保留不回复/无后续工作这一结束能力，避免无意义互相确认。
2. 做任务板、依赖、证据、提议与指派、转交接受，后台权限真实成立。
3. 做 Bot 消息真实入库/唤醒/忙队列，招募审批、ask_user 与协作记录。
4. 做编程角色模板、候选版本和合并确认，由外部 Agent 做隔离、测试、审查和获批交付。
5. 用已稳定的 M3 运行实例开发 M4 的一项小功能；候选版本在 development 环境测试，不热替换正在管理任务的核心。

交付：按5.0完成真实MCP/任务闭环与K01，开始自举，不把未完成控制/恢复宣传为首版完成。

### M4：控制与可靠性补齐

1. 做链/epoch/计轮事务、风险评估与继续/停止，预算账本与设置门禁。
2. 做记忆记录/检索/删除去重，Bot 管理、团队归档删除完整限制。
3. 做正常退出、中断持久状态、启动核对/恢复卡，不可接管的清晰处理。
4. 做版本适配的租约/hook/事件落盘导入，实际验证覆盖、拒绝和异常；不复用日志轮转删除恢复证据。
5. 做断流/审批失效/未知发送/备份恢复边界测试，修复已发现问题。

交付：按5.0完成控制/可靠性和先前延期子项。确有引擎能力缺失的未通过项必须报告；不得自行删除该首版要求。

### M5：三端试用交付

1. 完整中文/英文、窄屏与可访问性，去掉模拟入口，完成全部设置页面。
2. 各平台构建与安装运行，headless 无桌面依赖，最终包无 Node 开发依赖。
3. 补充开源贡献/开发/升级说明、第三方许可与 SBOM、校验值和支持矩阵。
4. 完整执行验收清单；再用交付版本完成下一项开发验证持续自举。

交付：I/J/K 全部与全清单回归，安装包、验收记录、已知问题列表。手动更新；无签名/公证标明试用状态。许可证由用户公开发布前确定，编码智能体不擅自添加许可证。

## 6. 报告与停止条件

每个里程碑提交记录：实现范围、运行命令、通过的验收 ID、真实证据位置、未通过原因和剩余功能。证据存 `docs/验证/` 的脱敏摘要；原始运行数据和账号材料存忽略区。

日常测试失败先定位代码。只有真正需要用户选择的范围变更、已有规则不可实现、缺必需工具或授权时才询问；不能把常规编码选择全部交还用户。

如果发现引擎能力与需求冲突，写出目标版本、能力、实际失败和最小影响；禁止偷偷切完全访问、绕过 hook 信任、修改原生配置/ACL/防火墙或创建新位置替代丢失资源。

禁止交付：假发送成功、假审批成功、假任务完成、把未知当零、跨团队可操作、自动重跑未知副作用、单测 mock 通过冒充真实模型验收、只开发聊天 UI 后称首版完成。
