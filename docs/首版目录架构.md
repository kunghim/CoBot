## 2. 依赖方向与放置规则

```text
cmd/desktop宿主 -> bootstrap -> app
                              app -> domain / engine接口 / store / events / guard
api/http -> app + contract
engine/codex -> engine接口 + platform（不导入 app 或 sqlite）
store/sqlite -> domain（不导入 app、http 或 codex）
collaboration -> 工具schema + ApiClient（stdio桥不打开DB）
desktop -> 原生能力 + bootstrap/session启动（不直接执行任务/审批）
domain -> 标准库
```

- 只有 bootstrap 组合真实 Codex 适配器、数据库和 app；不要让 HTTP/桌面各自实例化一套 app。
- 用户动作与 MCP 动作共享 app 权限/事务方法。handler 不直接 UPDATE/派 turn。
- `collaboration` 含独立的stdio bridge和server-side dispatcher两个职责：bridge只调用内部HTTP，dispatcher在核心内校验Principal并调用app；两者共享工具schema，dispatcher不能回调bridge形成环。不是整个包都不得调用app。
- engine 接口依据首个真实适配器定义，恢复/模型/审批能力可选；不写将来所有 provider 的万能方法。
- SQL 事务控制放应用动作与 store 协作处；不要在 Go domain 里操作数据库。
- 公共 OpenAPI DTO、domain、Codex DTO 分开，明确映射；不将一个结构体到处复用。
- 测试 fake engine 放 test 辅助文件/测试目录，不能在生产配置里静默回退 mock。
- 平台文件用 build tags/GOOS 后缀；独立 server 不导入 Wails，避免 headless 也需要桌面运行时。
- `cmd/cobot-desktop` 和 `internal/desktop` 的 Wails源码使用 `desktop` build tag；headless CI测试不编译桌面包，桌面CI显式带该tag。否则即使server不导入Wails，`go test ./...` 也可能被平台GUI依赖阻塞。
- Web路径不得因无window.go/Wails/Xcode而失败；目录选择、登录、授权、服务状态和完整业务均有纯浏览器/HTTP路径。平台原生桥只影响desktop宿主。
- 对外扩展先加现有业务模块和适配器；没有第二个真实需求不增加 registry、插件 loader、workflow DSL。

## 3. 共享前端的构建链

Vite `build.outDir` 指向 `../internal/webui/dist`。只有这个目录存发布资产，不再保留另一份 frontend/dist；清理逻辑只允许该已解析的构建目录，不能递归清空 internal/webui。

`internal/webui/assets.go` 使用嵌入 FS，Wails 与 Go HTTP 静态服务均使用它。业务请求始终直接 loopback HTTP，不经 Wails asset handler。桌面生成的原生绑定放 `frontend/wailsjs/` 并忽略；只绑定目录/窗口/启动，不绑定任务或审批业务。

为避免首次build依赖不存在的生成文件，前端 `platform/native-bridge.ts` 声明并封装Wails原生 `window.go.desktop.Bridge` 方法（Bootstrap/OpenDirectory/Quit），不静态import被忽略的wailsjs。浏览器检测无桥走自己的启动逻辑；不得造stub生成目录骗过构建。两端仍用同一ApiClient业务实现。

Wails项目在 `cmd/cobot-desktop`，保留根go.mod，不新增子module。v2.15.0官方CLI的SyncGoMod向父目录找go.mod，此布局有源码依据，不靠复制go.mod规避。配置最低为：

```json
{
  "version": "2",
  "name": "CoBot",
  "outputfilename": "cobot-desktop",
  "frontend:dir": "../../frontend",
  "frontend:install": "npm ci",
  "frontend:build": "npm run build",
  "wailsjsdir": "../../frontend",
  "build:dir": "../../.tmp/wails",
  "build:tags": "desktop"
}
```

`wailsjsdir`是父目录，Wails再追加wailsjs，不能设为 `../../frontend/wailsjs` 后得到双层目录。CLI与库锁相同版本，构建禁自动同步版本/自动tidy，锁更新在根显式处理；可使用 `wails build -tags desktop -nosyncgomod -m -skipembedcreate`。脚本统一定位仓库根，禁止另init第二前端。

Wails生成bindings会运行带bindings构建标签的程序。Bridge构造函数必须无副作用，真实核心初始化放OnStartup并显式排除bindings模式；生成时不创建profile数据、锁、登录或app-server。Bridge.Bootstrap在核心Ready后才响应。不能在main函数里先开业务核心再调用wails.Run。

首次 checkout 没有 dist，不能直接 `go build` 指望 embed 成功。流程固定为：

1. M1初始化package.json时用一次npm install生成锁；此后clean checkout一律 `npm ci --prefix frontend`。
2. `scripts/generate.*` 先生成OpenAPI类型（无需编译产品main），再 `npm run build --prefix frontend` 生成嵌入资产，不依赖Wails生成绑定。
3. Go测试/构建。Windows：`go build -o .tmp/bin/cobot.exe ./cmd/cobot`；macOS：`go build -o .tmp/bin/cobot ./cmd/cobot`。不能把文档括号示意 `[.exe]` 当真实文件名。
4. 需要原生检查且工具可用时，在桌面项目目录执行锁定Wails命令；产物汇总 `.tmp/dist/`。这不是本轮Web构建前置，缺原生工具不自动安装、不停止headless测试。

生产桌面包包含主桌面程序和同版本辅助 `cobot` 程序。macOS 放 app bundle 的 Contents/MacOS，Windows 放应用安装目录。辅助程序用真实相邻安装路径定位，不通过 PATH 误找别的版本，用于 MCP/hook；这是轻量辅助进程，不是第二个后台或 Node runtime。

独立 Web 发行只需 cobot 可执行文件，内部含前端/迁移/默认角色。辅助 MCP/hook 子命令在同一可执行文件里。

## 4. 开发、测试与发行脚本契约

下列是编码智能体必须提供的脚本接口；现在尚未实现，不能在交接时声称已可运行。

| 命令接口 | 行为 |
| --- | --- |
| `scripts/dev.ps1` / `scripts/dev.sh` | 显式 development，启动 Go 服务与 Vite；退出收回自己启动的开发进程 |
| `scripts/check.*` | 检查格式/静态分析、生成契约差异、前端类型与单测、build 资产、Go 测试及集成、Playwright |
| Windows `scripts/build.ps1 -Target server/desktop`，macOS `scripts/build.sh --target server/desktop` | 两平台等价参数；桌面发行默认production，headless仍要求显式 `--profile production`；输出版本与校验 |
| `scripts/generate.*` | 从 OpenAPI 生成 Go DTO/TS；固定工具版本，CI 检查生成差异 |
| `cobot serve --profile development/production [--data-root <path>]` | 单实例核心；默认development；临时测试根显式指定，启动时打印/打开受控Web入口 |
| `cobot mcp` | stdio 工具桥，stdout 只有协议，身份从受管进程环境/通道取得 |
| `cobot hook` | 适配目标版本 hook 事件，读本地租约并返回准确原生 JSON，离线不能依赖核心 HTTP |

生成工具固定为oapi-codegen v2（Go types）与openapi-typescript（TS），实际补丁版本在M1锁定，禁止浮动latest。生成DTO提交，生成前后无差异由CI检查；不生成另一套HTTP业务实现。

check默认只执行本轮Web/共享核心检查，不调用wails build、不要求Mac、签名、WebView2安装检查。另设显式desktop检查选项，在具备原生工具时运行；失败/未测单独报告，不能将真正的共享核心编译失败归为“壳未测”。Go headless的darwin交叉编译可作为静态辅助，不代表Mac运行验收。

生产运行不使用Vite。dev脚本先以development启动Go并取endpoint/一次性bootstrap，再启动严格端口5173的Vite，通过不入日志的进程环境把入口秘密交给开发入口；不写入源码或env持久文件。Vite用同源 `/api` 代理到该Go endpoint，cookie/CSRF按实际浏览器Origin处理；development只允许明确localhost/127.0.0.1:5173，端口冲突报告，不自动注册任意来源。

Playwright启动 `tests/e2e/host` 假引擎宿主，显式给 `.tmp/test-runs/{runId}/profile`；生产cmd没有mock开关，不可能因Codex不可用自动回退。R验收通过真实产品入口，不用该测试宿主。check脚本默认不执行R登录/模型用量或桌面重启动作。

检查脚本可下载项目声明的依赖，但不得自行安装系统工具、改 PATH/ACL 或创建替代资源。工具缺失按本机约定报告。首次依赖版本记录到锁文件，不在脚本里 `@latest`。

## 5. 用户数据目录（两环境同构）

```text
~/.cobot-dev/ 或 ~/.cobot/
├── config.json                        # 仅启动参数；业务设置在SQLite，不含token
├── data/cobot.sqlite                   # SQLite唯一业务事实；wal/shm同目录
├── backups/                            # 一致性升级前备份与版本清单
├── engines/codex/                      # 同环境共享私有CODEX_HOME/SQLite/凭据
├── roles/                              # 默认角色首次落地与用户版本化修改
├── workspaces/                         # 可供用户选择的默认工作位置，不自动绑定根
├── runtime/
│   ├── instance.lock                   # 生命周期锁
│   ├── instance.json                   # endpoint/instance/profile，不含授权秘密
│   ├── leases/{botId}.json             # 代际、运行、心跳、许可范围；原子更新
│   └── credentials/                   # 桥/实例发现所需受控短期凭据，不放团队目录
├── events/pending/{botId}/             # 未导入的恢复证据，不按日志规则随意删
├── events/imported/                    # 已导入归档，按保留规则清理
├── events/quarantine/                  # 损坏证据与导入失败原因
├── logs/                               # 脱敏、轮转、有限容量
├── cache/                              # 可重建缓存，不包含唯一业务事实
└── webview/                            # 开发/生产分别存放
```

profile 默认根不等于团队 cwd。团队 app-server 的启动 cwd 是该团队目录，不能启动在共享工作区根扩大 workspaceWrite 边界；私有状态路径通过配置传递，不通过把 cwd 设为引擎 home 实现。

`config.json` 只保存打开数据库前必需的启动参数（例如可选数据根、监听及日志配置），业务设置以SQLite settings为唯一事实源；不要双写默认模型、预算或语言到JSON和数据库并由两者抢优先级。

角色JSON最低含 schemaVersion/id/nameKey/instructions，变更带内容版本/摘要。默认角色嵌入只读，首次把可编辑副本放profile roles；用户改动校验后用于下一轮，并保存本轮角色快照。角色文件不是权限配置，不能通过修改JSON获得用户审批或跨团队能力；默认模型使用环境设置，文件不写作者专属模型名。

环境根包含凭据，不能选它本身作为团队目录；`workspaces/` 下可选的具体工作目录与其他运行资源分开。创建团队时默认推荐 profile workspaces 下具体目录，但仍需用户显式选择。

短期 runtime 凭据限制本机用户可读，不写入日志或 metadata；windows 不能把 chmod 返回成功当成 ACL 已验证。启动发现文件提供位置不是身份；另做受控秘密验证。

profileInstanceId首次建库持久生成，team.json.instanceId使用该值，重启不变；serviceEpoch为当前核心生命周期，engineEpoch为某app-server生命周期，两者每次重建改变。不要混成一个instanceId导致重启误认外来团队。旧Run待核对时不为它自动发新代际“允许执行”租约。

迁移不可操作 engines/codex 数据库。数据根不可跟随项目目录改变；源代码仓库不提交用户库、凭据、日志、缓存或安装包。

## 6. 团队目录的资源

```text
<用户明确选择的目录>/
├── 用户自己的文件/仓库...
└── .cobot/
    ├── team.json                      # schemaVersion/instanceId/profile/teamId/目录识别
    ├── context/                       # 团队与角色上下文快照，按需生成
    └── resources/                     # 外部交互资源引用，按任务用途创建
```

team.json 不存 token、数据库密码、桥授权或审批秘密。不是任务库、日志库、模型会话库。不得让 Agent 通过改它变更 owner/审批。

资源路径通过安全 join/规范化限制在 `.cobot` 内，不接受 `../` 或符号链接穿越后写入任意位置。不同 Bot 明确自身资源命名范围；共享资源更新原子化，不覆盖作者文件。

用户成果按任务保存，可在团队目录之外但必须有引擎权限；CoBot 只记录引用，不自行移动/提交/清理成果。删除团队保留此资源，标记后续被识别为未绑定；后续接管由用户决定，不自动移除。

## 7. 禁止的目录偏离

- 不能生成 backend/frontend/desktop 三个独立业务项目，也不增加第二个 Go module。
- 不把 cmd/cobot 入口写成业务大文件，不把 SQL/审批逻辑放 React 或 Wails binding。
- 不把日常 Codex home、项目 `.cobot` 和产品 data 互相链接，以避免会话污染或目录越权。
- 不提前建 plugin-market/cloud/git-service/office-runtime 等空架构。
- 不复制旧 Node Client 到生产服务；experiments 保留其验证定位。
- 大文件和原始账号数据不进 docs；文档中的跨机路径使用相对路径或 `~`，不写作者机器专属安装路径。
- docs子目录全部英文且被Git忽略；新版本的脱敏验收摘要放docs根Markdown。编译资产/实验源码位于既定源码位置，不误放本机archive；当前实现不依赖历史归档。
