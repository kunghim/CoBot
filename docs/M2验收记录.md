## 实现范围

- 迁移 00002：`teams`/`directory_bindings`/`bots`/`provider_sessions`/`messages`/`deliveries`/`runs`/`approvals`/`approval_decisions`/`approval_responses`/`idempotency`；`provider_sessions` 以 `bot_id` 为主键并保存 `engine_epoch`。
- `internal/engine/codex`：`app-server --stdio` JSON-RPC 客户端（单顺序读循环、请求/通知/服务端反向请求分流、16MB 行缓冲、ctx 有界超时、进程退出使在途请求全部失败）；`initialize`/`initialized` 握手；`thread/start`、`thread/resume`、`turn/start`、`turn/interrupt`；`item/*Approval` 反向请求按原样 `json.RawMessage` 请求号回复；`account/*`、`model/list`；stderr 经 `stderrLog` 进产品日志（warn 级）。
- `internal/engine`：`Server`/`ServerFactory`/`Callbacks`/`Notification`/`ApprovalRequest` 等窄接口，按首个真实适配器定义，不预写万能方法。
- `internal/app/scheduler.go`：每团队一个 app-server、每 Bot 一个 thread；派发串行领取、每 Bot 单活动 Run；engine 交互在 SQL 事务之外；`turn/start` 结果不确定时进入 `unknown` 并锁住该 Bot，不自动重试；`turn/completed` 映射 completed/failed/interrupted，合并 `item/completed` 的 agentMessage 正文后落库。
- `internal/app/teams.go`：目录规范化（组件级嵌套判定，不用字符串前缀）、目录唯一与嵌套冲突拒绝、`.cobot/team.json` 标记与 Git 本地 exclude（仅 `info/exchange` 幂等追加 `.cobot/`，不动共享 ignore）、分阶段创建（先原子预留绑定与成员，资源准备失败只翻成可重试的 error）。
- `internal/app/approvals.go`：审批双入口投影（队长全团队、成员仅自己，服务端过滤）、决定 CAS 与 `expectedRevision`、原选项快照、决定与引擎响应分离为 `queued/sent/unknown/expired`。
- `internal/app/engine_status.go`：引擎定位、版本探测、登录态投影与模型列表（不读出 token）。
- 前端：团队列表与新建团队、五种专业角色选择、会话消息流、SSE 事件消费、审批卡片（待处理 pager，`‹ i / n ›`，无轮播）、右侧审批历史只读、设置页引擎区块（路径/状态/模型/登录）。
- 接口：`internal/contract` 与 `frontend/src/api/generated` 由 `api/openapi.yaml` 生成（oapi-codegen v2.4.1、openapi-typescript 7.13.0），新增 teams/bots/messages/runs/approvals/engine/models 接口。
- 测试宿主：`tests/e2e/host` 假引擎（同一 stdio 协议，仅模型被脚本化：reply/approve/deny/fail）；`tests/e2e/specs` 三条 Playwright 用例驱动真实核心。

## 本阶段修复的真实缺陷

1. **跨引擎线程 ID 冲突（核心）**：`provider_thread_id` 只在单个 app-server 内唯一。两个团队各自启动引擎时，若引擎复用同一线程号（假引擎必然如此），`FindBotByThread` 命中错误的 Bot，第二个团队的 `turn/completed` 被解析到第一个团队的 Bot 而静默丢弃，界面永远等不到回复。修复为按 `engine_epoch` 限定查询（该列建表时即存在），并在 `finishRun` 补齐两条被静默吞掉的守卫日志。
2. **引擎 stderr 不可见**：引擎把诊断写在 stderr，而产品日志只在 debug 级输出，低于默认 info 阈值；失败的引擎在产品日志里不留痕迹。提升为 warn。
3. **E2E 多团队串扰**：一个核心为每个团队各起一个引擎进程，但所有引擎读同一个 `FAKE_CONTROL` 文件；审批用例把模式切成 `approve` 并只在成功路径复位，后续用例的引擎继承 `approve` 并阻塞在无人回答的审批上。控制文件改为按团队目录哈希命名，两侧同法归一。
4. **审批断言范围错误**：工作面板会合法保留同一条命令的审批历史，整页文本匹配同时命中待处理卡片与历史，`toBeHidden` 必然失败。断言改为限定在待处理卡片容器内。

## 已知问题与偏离

- HTTP 层 DTO 与 `internal/contract` 生成类型结构一致，但尚未全面改为引用生成类型（domain 仍被直接序列化一部分）；随 M3 接口扩展一并统一映射。
- 引擎 `Env` 为整体替换：`EngineEnv` 保留父环境（含 `FAKE_CONTROL`）并只覆盖 `CODEX_HOME`/`CODEX_SQLITE_HOME`。这是 E2E 能按键控制引擎的前提，也是产品行为（团队引擎继承核心环境）。
- `finishRun` 的两条守卫日志在真实账号场景下会因线程恢复/重启出现，属于预期诊断，不是错误。
- 未偏离用户已确认决定；`cobot mcp`/`cobot hook` 未提前占位实现（分别随 M3/M4 交付）。
