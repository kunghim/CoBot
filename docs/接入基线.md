## 1. 已处理前提

用户确认桌面与Go服务通信、私有环境官方登录、多团队并行等前提已经处理，不需要再独立做开发前spike。按既定方向实现产品，正常集成发现具体失败时再定位，不重新改架构或修复原生环境。

## 2. 历史证据与适用范围

| 内容 | 已有结论 | 边界 |
| --- | --- | --- |
| app-server接入 | Windows CLI 0.161.0的握手、真实流、多thread、正常resume、MCP调用与原生审批有证据 | 当时MCP业务送达是模拟，不是产品任务闭环 |
| 原生命令/文件 | 0.161.0临时优先MXC后，基础读写与批准/拒绝通过 | 不推断所有版本/平台都支持相同参数 |
| 会话污染 | 独立CODEX_HOME、CODEX_SQLITE_HOME及sqlite_home可保存真实thread，不进入原生日常会话库 | 是状态隔离，不是Windows账号/防火墙/系统沙箱资源完全隔离 |
| 开发/生产状态 | 两私有状态根各自恢复相同thread并记住前轮内容 | 正式产品根与所有故障场景未由这次实验实现 |
| 登录继承 | 空私有home不会自动继承日常登录 | 内部chatgptAuthTokens仅受控实验，不能用于首版正式默认 |
| Windows故障恢复 | 已测桌面自带0.162.0-alpha.17.2，保存prefer_mxc=true后完整重启桌面，受限命令与只读写入拒绝通过 | 旧elevated路径未修复，不能称所有沙箱路径都正常 |
| 命令共存 | 上述版本明确windows.sandbox=mxc，两个不同私有根与日常实例有限命令共存、退出/重启通过 | command/exec不是完整模型工具闭环，也不扩大成共享同根多团队的实测 |

上午已存在helper_sandbox_lock_failed，不能直接归因于晚上的会话隔离。重启后的偏好变化与底层锁失败完整原因尚未查明；恢复的是MXC执行路径，不是旧沙箱修复。

用户提供的已处理前提和本仓历史实测范围分别标注，不要求重新提交证明，也不把用户确认冒充本仓新增实验。

## 3. 必须沿用的实现约束

- 一团队一个app-server，一Bot独立thread，RPC/通知/反向审批准确关联。Node实验只供协议例子，生产使用Go。
- 团队进程cwd为团队目录；默认workspaceWrite会包含服务启动cwd，不能启动在公共根再期待单次请求cwd缩小范围。
- 每环境私有home与SQLite状态同根，团队共享该环境官方登录；开发/生产分别管理，不复制日常auth/config。
- Windows对子进程选择实际版本支持的MXC，不仅靠偏好开关；不能回退旧系统初始化或完全访问模式。macOS按实际支持策略适配。
- 启动检查真实二进制/版本/能力，不使用作者机器绝对路径；不为健康检查运行旧沙箱诊断。
- 不直接操作Codex SQLite；恢复仅依据受支持接口与受管事件，未知不重跑。
- 产品功能随开发验收，实验通过不能直接勾选任务投递、审批一致性、恢复或三端交付。
