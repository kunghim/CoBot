## 实现范围

- 迁移 00003：`tasks`/`task_dependencies`（双列外键）/`task_evidence`/`transfers`/`questions`；`messages` 增加 `source_bot_id` 与索引。
- `internal/domain/task.go`：任务五态（done 只能经确认）、证据、转交四态（offered/accepted/cancelled/stale）、问题三态与相应事件常量。
- `internal/store/sqlite/queries_tasks.go`：任务/依赖/证据/转交/问题全套查询；`HasCycleFrom` 环检测；`AnswerQuestion` 在同一事务内写回答、用户消息、投递并唤醒。
- `internal/auth/bottoken.go`：Bot 令牌库（内存、随引擎代际发放/回收）；桥接环境变量常量同放 auth，避免 collaboration→app 循环依赖。
- `internal/collaboration`：stdio MCP 桥（17 个工具，中文描述即模型唯一说明书；写工具强制 `idempotencyKey`；rejected/unavailable 渲染为 MCP 错误结果而非埋在成功负载里的状态）+ 核心侧 dispatcher（30 秒超时、按工具的参数结构、队长/同队校验）。
- `internal/app`：`CreateTask`（依赖校验含创建期环检测、同队约束；派发在事务内入队）、`UpdateTaskStatus`（review 需证据、done 拒绝直改）、`ConfirmTask`、`SubmitEvidence`、`AssignTask`（旧负责人 Run 未知/在途时拒绝）、两阶段转交（接受时取消旧负责人未送达派发、给新负责人入队）、`AskUser`（不阻塞 turn）、`AnswerQuestion`（仅用户、恰好一次）、`SendMessageFromBot`（仅成员、同队、幂等重放返回 duplicate）、`ListCollaboration`（Bot 看与单个同队同伴的双向段；用户看指定成员的完整记录）、`RequestMember`（招募审批，批准即 `AddBot`，失败如实记 unknown）、`SubmitMergeRequest`（要求证据并绑定候选/目标/执行目录）。
- 运行身份：`provider_sessions.engine_epoch` + `runs.engine_epoch`；thread→bot 查找与陈旧完成守卫全部按代际限定；审批暂停保留引擎 turn id；跨连接 resume 时重绑代际。
- 引擎线程注入 `mcp_servers.cobot` 配置（`cobot mcp` 子命令，同版本自解析二进制，env 携带 endpoint+bot token）。
- HTTP 面：`/teams/{id}/tasks`、`/tasks/{id}`（PATCH 状态；owner 变更只走 AssignTask）、`/tasks/{id}/evidence|confirm|transfers`、`/transfers/{id}/accept|cancel`、`/questions`、`/questions/{id}/answers|cancel`、`/bots/{id}/collaboration`、`/internal/v1/collaboration`；OpenAPI 3.0.3 补齐并声明全部 security（redocly lint 0 error）。
- 前端：任务看板（状态/负责人/依赖、新建、展开详情、证据提交、两阶段转交发起-接受-撤销）、待你回答（置顶开放问题、选项一点即答、撤回）、协作记录（只读、标注参与者）；状态规则收敛在 `taskFlow.ts` 纯函数（7 项单测）；M3 后端错误键中英文全部补齐。

## 本阶段修复的真实缺陷

1. **审批暂停覆盖引擎 turn id（核心）**：`waiting_approval` 落库时把 run UUID 写进了 `provider_turn_id`，审批结束后真正的 `turn/completed`（引擎自身 turn id）被陈旧守卫永久丢弃，界面永远等不到继续。修复为保留 `run.ProviderTurnID`；同时 `UpdateRunStatus` 不再 COALESCE——turn id 与 engine epoch 成对总是写入，跨连接 resume 时重绑 `provider_sessions.engine_epoch`（`d041d87`）。
2. **用户读协作记录恒为空**：用户读指定成员时把 (member, member) 传给存储层，只能命中产品从不创建的自发自收消息。改为用户路径取该成员的完整记录（发或收），Bot 的同伴段查询不变（`5338527`）。
3. **创建期依赖环不拦截**：环检测因 `taskID != ""` 守卫跳过了创建路径，任务可以依赖一个反向依赖它的任务。守卫移除并加存储层环单测（`3f1f0a3`）。
4. **MCP 拒绝不为模型可读**：dispatcher 返回 rejected/unavailable 时桥以成功结果返回，模型看不到失败原因。改为 MCP 错误结果（IsError）渲染（`e4425bb`）。

## 已知问题与偏离

- Bot 忙时的协作消息排队与用户消息共用同一投递队列与领取机制，但没有“Bot 忙时收到 Bot 消息”的专门集成用例；以共享机制的既有证明 + 持久化交叉验证覆盖，随 M4 恢复用例一并补。
- `internal/contract` 生成类型与 HTTP DTO 的统一映射（M2 遗留）尚未完成，随 M4 接口扩展一并处理。
- 转交接受要求旧负责人 Run 已结束（E03），这是产品规则而非测试妥协；集成测试按该规则编排（等待 Run 结束后再接受）。
- 前端任务看板的“状态按钮”只镜像服务端规则以避免必然失败的按钮，最终授权始终在服务端。
- 未偏离用户已确认决定；`cobot hook`/记忆/链路预算未提前实现（随 M4 交付）。
